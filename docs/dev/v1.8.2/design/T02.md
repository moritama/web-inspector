# T02 設計メモ: content-script の IIFE 化（B）

## 目的

同じタブを再読み込みせずに 2 回調べると、2 回目の `executeScript({ files })` で content-script がトップレベルの `const` の重複宣言（SyntaxError）になり、二重注入の印に届かない不具合を直す。content-script を IIFE で出す 2 段目のビルドを足し、CI で IIFE でない出力を不合格にする（H6、指示書 §5.1）。

## 仕様の解釈

受け入れ条件（指示書 §6 T02）と §5.1 を、テストで確かめられる形に言い直す。

1. **メインのビルドから content-script を外す**（§5.1）: `vite.config.ts` の既定のエクスポートの `build.rollupOptions.input` に `src/content/content-script.ts` が無い。popup・dashboard・service-worker は残る（陰性）。
2. **2 段目のビルド**（§5.1）: `vite.config.ts` が `contentScriptBuildConfig(outDir)` を export し、その設定は
   - 入力は `src/content/content-script.ts` だけ
   - `rollupOptions.output.format: 'iife'`、`inlineDynamicImports: true`、`entryFileNames: 'content/content-script.js'`
   - `build.emptyOutDir: false`（1 段目の出力を消さない）、`build.outDir` は渡した `outDir`
   - その設定で build すると、`<outDir>/content/content-script.js` の 1 ファイルだけ（.js は他に出さない）
3. **IIFE であること**: 出力は、先頭のコメントと `'use strict'` を除くと関数式の即時実行（`(function`・`(() =>`・`(async`・`!function`）で始まり、トップレベルの `const` / `let` / `class` / `var` / `import` / `export` で始まらない。行頭の `import` / `export` も無い（総合チェック C20 と同じ基準）。
4. **2 回注入してもエラーが出ず、リスナーが重複しない**（受け入れ 1。E2E の代わりに Vitest でも確かめる）: 出力を `node:vm` の **1 つのコンテキスト**で 2 回実行する。`executeScript({ files })` は同じフレームの、拡張機能ごとの isolated world に classic script として評価されるので、トップレベルの `const` は 2 回目で重複宣言になる。これと同じ条件で、
   - IIFE の出力は 2 回とも例外を投げず、`chrome.runtime.onMessage.addListener` は 1 回だけ呼ばれ、`globalThis.__WEB_INSPECTOR_CONTENT_SCRIPT_INJECTED__ === true`
   - 自己確認（陰性）: 同じソースを ES モジュールの形（format `es`）で出すと、2 回目で「Identifier '…' has already been declared」の SyntaxError になる（テストの方法が不具合を再現できることの確認。実装の前から通る）
5. **リポジトリの設定での build**（受け入れ 3「check-size が通る」を含む）: リポジトリの `vite.config.ts` を設定ファイルにして、`outDir` だけを一時ディレクトリに上書きして `build()` すると（`npm run build` の `vite build` と同じ設定）、
   - `content/content-script.js` が IIFE で、4 と同じく 2 回実行してもエラーにならない
   - `popup.html`・`dashboard.html`・`background/service-worker.js`・`manifest.json` が残る（2 段目で消さない）
   - `content-script` を含むファイルは `content/content-script.js` だけ（`assets/` にチャンクを出さない）
   - `checkSizes`（`scripts/ci/check-size.mjs`）で dist の区分が `fail` でない（DB は固定 DB を渡す）
   - 2 段目は、1 段目が解決した `outDir` に出す（`dist` を直書きしない）。テストは `outDir` を上書きするので、直書きだと失敗する
6. **CI のチェック**（受け入れ 2）: `scripts/ci/check-content-script-iife.mjs` を足す。
   - `checkIifeSource(text)` は 3 の基準で合否と理由を返す。陽性（圧縮・整形・アロー関数・先頭コメント・`!function`）と陰性（トップレベルの const・let・class・var、`'use strict'` やコメントの後の const、import で始まる、IIFE の後の行の export、関数宣言だけ、空、コメントだけ）
   - 実際のビルドの出力でも確かめる: format `es` の出力は不合格、format `iife` の出力は合格
   - `checkContentScriptIife({ file })` はファイルを読んで判定する。ファイルが無ければ不合格（黙って通さない）
   - CLI は `--file <path>`（既定は `dist/content/content-script.js`）。合格で終了コード 0、不合格・ファイルなしで 0 以外。不合格のとき出力にファイルのパスが出る
   - `.github/workflows/ci.yml` の、`npm run build` を実行するジョブで、その後に `node scripts/ci/check-content-script-iife.mjs` を実行する。build より前には置かない。`continue-on-error: true` を付けない
7. **service-worker.ts のコメント**（§5.1 の 4 つ目）: `files: ['content/content-script.js']` の直前（8 行以内）のコメントが、IIFE で出していることに触れる（「IIFE」の文字を含む）。

**曖昧だった点と判断**

- 「E2E：同じタブを再読み込みせずに 2 回調査して、ページのコンソールにエラーが出ない。リスナーが重複しない」は E2E（人が実行）で確かめる。Vitest でも、上の 4・5 で同じ条件（同じグローバルで 2 回評価）を再現して確かめる。isolated world のエラーはページのコンソールに出ないことがあるので、E2E では調査の結果の `coverage` に注入の失敗が入らないことと、isolated world で `addListener` の呼び出しを数えることも見る（下の E2E の仕様）。
- §5.1 は「先頭がトップレベルの `const` / `let` でない」としか書いていないが、総合チェック C20 は `class`・`var`・`import`・`export` も不合格にする。CI のチェックと C20 が食い違わないよう、同じ基準にした（`var` の重複は SyntaxError にならないが、IIFE でない出力なので不合格でよい。rollup の iife の出力は合格するので、警告を増やしすぎない）。
- 「IIFE の後にトップレベルの const が続く」形は、先頭だけを見る §5.1 の基準では検出できない。rollup の iife は 1 つの即時実行の式だけを出すので、テストに入れない（書きすぎを避ける）。代わりに 4・5 の 2 回実行のテストで実際の出力を確かめる。
- 2 段目のビルドをどこで起動するかは指示書に無い。`package.json` の `build` スクリプトの書き換えは K2.1 の「`scripts` の追加のみ」の外になるので、`vite.config.ts` の中のプラグイン（`closeBundle` で 2 段目を `build()`）で起動する。テストは `npm run build` を使わず、Vite の `build()` に `vite.config.ts` を渡して確かめる。

## 実装の方針

変更してよい場所: `vite.config.ts`、`scripts/ci/`（新規ファイル）、`.github/workflows/ci.yml`（手順を 1 つ足すだけ）、`src/background/service-worker.ts`（コメントだけ）、`scripts/test-e2e-smoke.mjs`、`docs/`（設計メモを除く。任意）。`tests/` と設計メモは変更しない。`package.json` は変えない。

1. **`vite.config.ts`**
   - `build.rollupOptions.input` から `'content-script'` を外す。`entryFileNames` の `content-script` の分岐は消してよい（残っても害はない）。`test.setupFiles` はそのまま（`tests/advisory-fixture-default.test.ts` が見ている）。
   - 新設（named export）:
     ```ts
     import { build, defineConfig, type InlineConfig, type Plugin } from 'vite';

     /** content-script を IIFE で出す 2 段目のビルドの設定（v1.8.2 T02 / H6）。outDir は 1 段目と同じ出力先 */
     export function contentScriptBuildConfig(outDir: string): InlineConfig {
       return {
         configFile: false, // vite.config.ts を読み直さない（プラグインの再帰と、1 段目の入力の混入を防ぐ）
         root: __dirname,
         publicDir: false, // public/ は 1 段目が写す
         logLevel: 'warn',
         build: {
           outDir,
           emptyOutDir: false,
           target: 'esnext',
           rollupOptions: {
             input: resolve(__dirname, 'src/content/content-script.ts'),
             output: {
               format: 'iife',
               inlineDynamicImports: true,
               entryFileNames: 'content/content-script.js',
             },
           },
         },
       };
     }

     /** 1 段目の書き出しの後に、2 段目（content-script の IIFE）をビルドする */
     function contentScriptIifePlugin(): Plugin {
       let outDir = resolve(__dirname, 'dist');
       return {
         name: 'web-inspector-content-script-iife',
         apply: 'build',
         configResolved(config) {
           outDir = resolve(config.root, config.build.outDir);
         },
         async closeBundle() {
           await build(contentScriptBuildConfig(outDir));
         },
       };
     }
     ```
     既定のエクスポートの `defineConfig({ plugins: [contentScriptIifePlugin()], build: { … }, test: { … } })` に足す。
   - テストが前提にしている公開 API: `vite.config.ts` の `default`（オブジェクトか、`{ command, mode }` を受ける関数）と `contentScriptBuildConfig(outDir: string): InlineConfig`。テストは `build({ ...contentScriptBuildConfig(dir), logLevel: 'silent' })` と、`build({ configFile: '<repo>/vite.config.ts', root: '<repo>', logLevel: 'silent', build: { outDir: dir } })` を呼ぶ。
   - `configFile: false` を必ず付ける。付けないと 2 段目が `vite.config.ts` を読み、popup などの入力とプラグインが混ざる（テスト「別のチャンクを出さない」が落ちる）。
   - `output.name` は付けない（content-script は外から読む値を持たない。rollup は使われない export を落とす）。
2. **`scripts/ci/check-content-script-iife.mjs`**（新規。`scripts/ci/check-size.mjs` の書き方に合わせる）
   ```js
   /** @returns {{ ok: boolean, reason: string }} */
   export function checkIifeSource(text) { … }
   /** @param {{ file?: string }} [options] 既定は <repo>/dist/content/content-script.js
    *  @returns {{ ok: boolean, path: string, reason: string }} */
   export function checkContentScriptIife(options = {}) { … }
   ```
   - 判定（C20 と同じ）: `text` から先頭の空白・`/* … */`・`// …` を繰り返し除き（`/^(?:\s|\/\*[\s\S]*?\*\/|\/\/[^\n]*\n)*/`）、続く `'use strict'` / `"use strict"`（と `;`・空白）を除いた本文 `body` で、
     - `/^(const|let|class|var)\s/.test(body)` または `/^(import|export)\b/m.test(body)` なら不合格（理由: 「先頭がトップレベルの宣言（同じフレームへの 2 回目の注入で SyntaxError になる）」の趣旨）
     - `/^(\(\s*(function\b|\(\s*\)\s*=>|async\b)|!function\b)/.test(body)` でなければ不合格（理由: 「先頭が IIFE に見えない」の趣旨）。空・コメントだけもここで不合格
     - それ以外は合格（`reason: ''`）
   - ファイルが無いときは `{ ok: false, path, reason: '…が無い（npm run build の後に実行する）' }`。
   - CLI: `--file <path>` を `path.resolve` する。合格なら `console.log('[content-script] OK: IIFE …')` で終了コード 0、不合格なら `console.error('::error file=<path>::…<理由>')` で終了コード 1。入口の判定は `check-size.mjs` の `isMainModule()`（`fs.realpathSync(process.argv[1])` と `import.meta.url` の比較）と同じにする。
3. **`.github/workflows/ci.yml`**: ジョブ `verify` の「Check advisory DB and dist size limits」の後（`npm run build` の後）に手順を 1 つ足す。他は変えない。
   ```yaml
         - name: Check content-script is an IIFE
           run: node scripts/ci/check-content-script-iife.mjs
   ```
4. **`src/background/service-worker.ts` 489 行のコメント**: 実態に合わせる。例: `// 1. 調査実行時に chrome.scripting.executeScript で Content Script を注入する。content-script.js は IIFE で出している（vite.config.ts の 2 段目のビルド）ので、同じフレームへ 2 回目を注入しても重複宣言にならず、先頭の印（CONTENT_SCRIPT_GUARD_KEY）でリスナーの二重登録を防ぐ`。コード（`files: ['content/content-script.js']` など）は変えない（`tests/service-worker.test.ts` がこの引数を見ている）。
5. **`scripts/test-e2e-smoke.mjs`**（実装の工程で足し、人が実行する。総合チェック C21 は `already been declared` か `二重注入` などの文字を探す）
   - 対象: `http://localhost:3000/react18-app`（既存の `inspectUrl` で開いた localhost のタブ）。
   - 手順:
     1. `page.on('pageerror')` と `page.on('console')`（`msg.type() === 'error'`）でページのエラーを集める。
     2. `inspectUrl(url)` で 1 回目、続けて再読み込みせずに `inspectCurrentTabAgain()` で 2 回目を調べる。
     3. `serviceWorker.evaluate` でタブ ID を取り、`chrome.scripting.executeScript({ target: { tabId }, func })`（world は既定の ISOLATED）で、isolated world の `chrome.runtime.onMessage.addListener` を包んで呼び出し回数を `globalThis.__e2eAddListenerCalls` に数えるようにする。続けて 3 回目の `inspectCurrentTabAgain()`、もう一度 `executeScript({ func })` で `__e2eAddListenerCalls` と `globalThis.__WEB_INSPECTOR_CONTENT_SCRIPT_INJECTED__` を読む。
     4. 2 回目が本当に実行されたこと（SyntaxError で止まっていないこと）を確かめるため、最後に `executeScript({ func })` で `__WEB_INSPECTOR_CONTENT_SCRIPT_INJECTED__` を消してから `executeScript({ files: ['content/content-script.js'] })` を実行し、`__e2eAddListenerCalls` が 1 増えることを見る。その後 `page.reload()` で後片付けする。
   - 確かめること（満たさなければ `throw new Error('… 二重注入 …')`）:
     - 2 回目・3 回目の結果を `JSON.stringify` した文字列に「注入に失敗」と「already been declared」が無い。`coverage` の DOM の収集の理由が 1 回目と同じ。
     - 3 の `__e2eAddListenerCalls` が 0（印でスキップされ、リスナーが重複しない）、印が `true`。
     - 4 で `__e2eAddListenerCalls` が 1 増える（2 回目の注入でもスクリプトが実行される）。
     - 1 で集めたページのエラーに「already been declared」を含むものが無い。
   - 製品のコードに E2E 用の分岐を足さない。

## 期待値を変えた既存テスト

既存テストへの影響を確かめた結果:

- `tests/ci-workflow.test.ts` はアクションの SHA 固定・permissions・check-size の位置を見ている。足す手順は `run:` だけで `uses:` も permissions も足さないので壊れない。
- `tests/ci-check-size.test.ts` は合成の dist で測るので影響しない。
- `toEqual({ ... })` などで vite の設定やビルドの出力を全体比較しているテストは無い。

## 実装の担当への注意

- `contentScriptBuildConfig` には必ず `configFile: false` を付ける（付けないと 2 段目が `vite.config.ts` を読み直し、プラグインが再び 2 段目を起動し、popup などの入力も混ざる）。
- 2 段目の出力先は、1 段目が解決した `outDir`（`configResolved` の `config.build.outDir` を `config.root` から解決したもの）を使う。`'dist'` を直書きしない（テストは outDir を一時ディレクトリに上書きして確かめる）。
- 2 段目の `emptyOutDir` は `false`。`true` だと 1 段目の出力（popup.html・service-worker.js など）が消える。
- 出力のパス `content/content-script.js` と、`service-worker.ts` の `files: ['content/content-script.js']` は変えない。`manifest.json`（`public/`）に content_scripts を足さない（オンデマンド注入のまま）。
- 二重注入の印（`CONTENT_SCRIPT_GUARD_KEY`・`initContentScript`）はそのまま生かす（H6）。content-script.ts の中身は変えなくてよい（export は rollup が落とす。`output.name` は付けない）。
- `package.json` の `build` スクリプトは変えない（K2.1 で許されているのは版と `scripts` の追加だけ）。2 段目は `vite.config.ts` のプラグインから起動する。
- `npm run watch`（`vite build --watch`）で `closeBundle` が毎回の再ビルドで呼ばれるかは確かめていない。watch は受け入れ条件の外なので、動かなくても止めずに WORKLOG に書く（`npm run build` と CI が正）。
- `ci.yml` は手順を 1 つ足すだけ。他の手順・ジョブ・アクションの SHA・permissions を変えない。
- 外部への通信・新しいセキュリティチェックは足さない。`HEADER_DEPENDENT_CHECK_PREFIXES` は関係しない。依存パッケージを足さない。
- `docs/MAINTENANCE_GUIDE.md` などにビルドの構成（入口の一覧）が書かれていれば、2 段目のビルドがあることを足してよい（任意）。
