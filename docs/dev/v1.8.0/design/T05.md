# T05 設計メモ — 一括取得の待ち方（SPA）

## 目的

`scripts/collect-reports.mjs` で、`#/` に移る SPA でも取得のたびに結果が揺れないよう、「URL が一定時間変わらない」かつ「DOM の変化が一定時間止まっている」まで待つ。待ちには上限を設け、上限に達したサイトは `_summary.md` に「待ち打ち切り」と記録する。

## 仕様の解釈

| # | 受け入れ条件・指示 | テストで確かめる形 |
| --- | --- | --- |
| A1 | test-server のそのページを 3 回取得して、技術の一覧が 3 回とも同じ | 人が朝に実行する（サンドボックスでは実行しない）。単体テストでは、同じ経過をたどる偽のページを `waitForSettle` で 3 回待ち、3 回とも同じ結果になることだけを確かめる |
| A2 | 待ち方の判定関数は、ブラウザなしの単体テストを持つ | 純粋関数 `judgeSettle(samples, opts)` と、観測・時計・待ちを差し替えられる `waitForSettle(probe, opts)` を、ブラウザなしで確かめる |
| B1 | 「URL が一定時間変わらない」かつ「DOM の変化が一定時間止まっている」まで待つ | 陽性: 両方が settleMs 以上変わらなければ settled（ちょうど settleMs を含む）。陰性: URL だけ止まっている／DOM だけ止まっている／settleMs 未満なら waiting。`#` 以降だけの変化も URL の変化とする |
| B2 | 待ち時間には上限を設ける | 変わり続けて maxWaitMs に達したら timeout。達する前は waiting。上限は最初の観測の時刻から数える。`waitForSettle` は上限を大きく超えて待たない |
| B3 | 新しい引数 `--settle-ms`（既定 1500） | `parseArgs([]).settleMs === 1500`、`--settle-ms 3000` で 3000。負の数・数値でない値・値なしはエラー。上限 `settleMaxMs` は有限で settleMs の既定より大きい |
| B4 | 上限に達したサイトは _summary.md に「待ち打ち切り」と記録する | `buildSummary` に `settle: { status: 'timeout' }` の結果を渡すと、そのサイトの表の行に「待ち打ち切り」が出る。`settled` の結果と、`settle` の無い従来の結果の行には出ない |
| B5 | test-server に、数百ミリ秒後に `#/` へ移り、さらに遅れて技術の印を描画するページを追加する | `test-server/server.mjs` に `/spa-settle` の経路がある（サーバーは import すると待ち受けを始めるので、ソースの文字列だけを見る）。ページの挙動は A1 で人が確かめる |

解釈と理由:

- **URL の比較**: `#` 以降を含めた URL 全体の文字列で比べる。SPA が `#/` に移ることがこのタスクの対象なので、ハッシュの変化も「URL の変化」とする。
- **DOM の変化**: ページ内の MutationObserver が数えた変化の累計（`domMutations`）が前の観測と違えば変化とする。値が減った場合（遷移で数え直した場合）も変化とする。
- **境界**: 最後の変化から `settleMs` ちょうど経った時点で落ち着いたとする（`>=`）。
- **上限と落ち着いた条件が同時に成り立つ場合**: 落ち着いたとする（打ち切りの誤記録を避ける。安全側）。
- **観測の例外**: 遷移中などで観測（`page.evaluate`）が例外を投げた場合は、失敗にせず「変化があった」として待ち続ける。
- **上限の値**: 指示書の新しい引数は `--settle-ms` だけなので、上限は CLI 引数にせず、`parseArgs` の戻り値 `settleMaxMs`（既定 15000 を推奨）として持つ。テストは「有限で、settleMs の既定より大きい」ことだけを見る。
- **`--wait`**: 既存の引数と既定（2000）は変えない（既存テストと利用者の手順を壊さない）。待ちの順番は「実装の方針」のとおり。
- **_summary.md の記録の場所**: 表の行（そのサイトの行）に「待ち打ち切り」が入ること。列（備考の列など）や、先頭の集計行に件数を足すかどうかは実装に任せる。テストは行の中に語があるかだけを見る。

## 実装の方針

変更するファイル: `scripts/collect-reports.mjs`、`test-server/server.mjs`（どちらも実装の工程で変更してよい場所）。

1. **`judgeSettle(samples, { settleMs, maxWaitMs })`**（`scripts/collect-reports.mjs` から export。純粋関数）
   - `samples`: 時刻順の観測の配列。各要素は `{ at: number /* ms */, url: string, domMutations: number }`
   - 戻り値: `{ status: 'waiting' | 'settled' | 'timeout', elapsedMs: number, stableMs: number }`（テストが見るのは `status` だけ）
   - 規則:
     - 空なら `waiting`
     - `lastChangeAt` = 前の要素と `url` か `domMutations` が違う最後の要素の `at`。無ければ最初の要素の `at`
     - `stableMs = 最後の at - lastChangeAt`、`elapsedMs = 最後の at - 最初の at`
     - `stableMs >= settleMs` なら `settled`（上限より優先）
     - それ以外で `elapsedMs >= maxWaitMs` なら `timeout`
     - それ以外は `waiting`
2. **`waitForSettle(probe, { settleMs, maxWaitMs, intervalMs = 100, now = Date.now, sleep })`**（export。async）
   - `probe: () => Promise<{ url: string, domMutations: number }>`
   - `sleep` の既定は `(ms) => new Promise((r) => setTimeout(r, ms))`
   - 開始時刻 `now()` から、観測 → `judgeSettle` → `waiting` なら `sleep(intervalMs)` を繰り返す
   - `probe` が例外を投げたら、その回は前回と必ず違う観測（例: `{ url: '', domMutations: -1 }` と前回の値を区別できる番兵）として記録する。reject しない
   - 戻り値: `{ status: 'settled' | 'timeout', waitedMs: number }`（`waitedMs = 終了時の now() - 開始時の now()`）
   - 時刻はすべて `now()` で取る（`at` も `now()`）。`Date.now()` を直接呼ばない（テストは偽の時計を渡す）
3. **`parseArgs`**
   - `opts.settleMs`（既定 1500）。`--settle-ms <ms>` で指定。`Number.isFinite` でない・負の値は `Error`（既存の `--wait` と同じ書き方）
   - `opts.settleMaxMs`（既定 15000 を推奨。CLI 引数は足さなくてよい）。`settleMs >= settleMaxMs` の指定はエラーにするのを推奨（テストはしない）
   - 先頭の使い方のコメントに `--settle-ms` を足す
4. **`inspectOne`**
   - `page.goto` の前に `page.addInitScript` で、文書ごとに MutationObserver を入れ、変化の数を `window` のプロパティ（例: `__wiSettleMutations`）に数える。`observe` の対象は `document`（documentElement が無い時点では作られ次第）で、`childList: true, subtree: true, characterData: true` を推奨（`attributes` はアニメーションで止まらないページが多いので外す）
   - 現在の `load` → `networkidle`（最大 10 秒）の後、`waitForTimeout(opts.waitMs)` の前に `waitForSettle` を呼ぶ。`probe` は `{ url: page.url(), domMutations: await page.evaluate(() => window.__wiSettleMutations ?? 0) }`
   - 結果を戻り値に `settle: { status, waitedMs }` として返し、`main` で `results` の要素に `settle` を入れる。`timeout` のときは `notes` にも「待ち打ち切り」を入れてよい（行に二重に出ても可）
5. **`buildSummary`**
   - `r.settle?.status === 'timeout'` の行に「待ち打ち切り」を出す（備考の列に足すのを推奨）。`settle` が無い・`settled` の行には出さない
6. **`test-server/server.mjs`**
   - `/spa-settle` の経路を足す。HTML は最初は技術の印を持たず、数百ミリ秒後（例: 300ms）に `location.hash = '#/'` で移り、さらに遅れて（例: 900ms）技術の印（例: 既存のページと同じ `window.jQuery.fn.jquery` の設定と、`/lib/bootstrap-…` のような既存の経路の `<link>`、または Vue / React の印になる要素）を描画する。印は既存のルールで検出できるもの、かつ test-server の既存の経路で返せるものにする
   - ナビゲーションのリンクと起動時のログに足す
   - インラインの `<script>` は test-server のページなので可（拡張の `src/` の規則の対象外）

テストが前提にしている公開 API: `scripts/collect-reports.mjs` の `judgeSettle`・`waitForSettle`・`parseArgs`（`settleMs`・`settleMaxMs`）・`buildSummary`（結果の `settle` フィールド）。`test-server/server.mjs` の `/spa-settle` の文字列。

## 外部の事実

- Playwright の `page.addInitScript` は、ページが遷移するたび（子フレームの追加・遷移を含む）に、文書が作られた後・ページのスクリプトが動く前に評価される。MutationObserver を入れる場所の根拠 — https://playwright.dev/docs/api/class-page （2026-11-12 確認）
- Playwright の `waitUntil: 'networkidle'` は「DISCOURAGED」（500ms 通信が無いことを待つ。準備の判定には使わないよう書かれている）。networkidle だけでは SPA の描画を待てないことの裏付け。既存の networkidle の待ちは残す — https://playwright.dev/docs/api/class-page （2026-11-12 確認）
- `page.url()` の文書には戻り値の説明が無い（`#` 以降を含むかは文書では未確認）。実装の担当は `page.url()` が `#` 以降を含まない場合に備え、`probe` で `page.evaluate(() => location.href)` を使ってもよい
- MutationObserver（DOM の変化の通知）は WHATWG DOM Standard の機能 — https://dom.spec.whatwg.org/#mutation-observers （今回は一次資料を開いて再確認していない。判定の規則はこの事実に依存しない）

## 実装の担当への注意

- `scripts/collect-reports.mjs` は `tests/report-lint.test.ts` からも import される。import の時点で副作用（ブラウザの起動など）を起こさない。既存の `parseArgs`・`buildSummary` の既存テストの期待値（`--snapshot`・`--timeout`、合否の表示）を壊さない。
- `waitForSettle` の中で `Date.now()` や `setTimeout` を直接使わない（`now`・`sleep` の引数を使う）。偽の時計で回すテストが無限ループになる。
- `test-server/server.mjs` は import すると port 3000 で待ち受けを始める。テストからは import しない前提なので、待ち受けを export の形に変えるリファクタリングは不要（指示に無い）。
- `npm run reports:collect` はエージェントは実行しない（外部にアクセスするため）。A1 は人が朝に実行する。
- 拡張機能（`src/`）は変更しない。このタスクは一括取得のスクリプトと test-server だけ。
- `_summary.md` の既存の列の順と見出しは変えないのを推奨（備考の列に足す）。
