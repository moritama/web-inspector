# T02 CI: DB だけのリリースの予行とサイズ上限 — 設計メモ

## 目的

コードの PR の段階で「DB だけの自動リリース」（manifest の版に 4 つ目の番号が付き、DB の dataVersion が進む）を作業ツリーの一時コピーで再現し、1.7.1.1 のようにテストが落ちてリリースが止まる事態をマージ前に見つける。あわせて、G7 のサイズの上限を CI で確かめる。

## 仕様の解釈

| # | 指示書 | 解釈（テストで確かめること） |
| --- | --- | --- |
| B1 | `scripts/ci/rehearse-db-release.mjs` を作る。作業ツリーの一時コピーで `bump-db-revision.mjs` を実行し、DB の dataVersion を進めて（integrity も再計算）、`npm test` を走らせる | `rehearseDbRelease(options)` が (1) 一時コピーを作り、(2) **コピーの中の** `scripts/advisories/bump-db-revision.mjs` を実行して manifest の版を `nextDbRevision(元の版)` にし、(3) コピーの DB の dataVersion を元より後の正しい日付（YYYYMMDD）にし、`integrity.digest` を `sha256(JSON.stringify(libraries))` で計算し直し、(4) コピーを作業ディレクトリにしてテストのコマンド（既定 `npm test`）を走らせる。テストのコマンドの終了コードが 0 なら `ok: true` |
| B2 | 元の作業ツリーは変更しない | 予行の前後で、元のツリーのファイル（追加・変更・削除）が変わらない。一時コピーは元のツリーの外（`os.tmpdir()` の下）に作り、既定では終了後に消す |
| B3 | （B1 の補足）コピーに含めるもの | `.gitignore` で除外されるもの（`dist/`・`reports/` など）はコピーしない。古いビルドを測らないため、また実サイトの取得結果（`reports/`）を持ち出さないため。`node_modules/` はコピーせず、元の `node_modules` へのシンボリックリンクを置く（`npm test` に必要。コピーすると遅い） |
| B4 | 受け入れ条件 1「現在のツリーで予行が通る」 | (a) CI のジョブ `db-release-rehearsal` で、既定の `npm test` による予行が通る（PR の CI で確かめる）。(b) Vitest の中では、全体の `npm test` を入れ子に走らせない代わりに、現在のツリーのコピーで版と dataVersion を進め、テストの代わりに `scripts/validate-advisories.mjs`（スキーマ・dataVersion の書式・integrity の検証）を走らせて通ることを確かめる |
| B5 | 受け入れ条件 2「旧来の書き方（manifest の版を完全一致で比べる）のテストを一時的に 1 件足すと予行が失敗する」 | 合成の作業ツリーに「manifest の版 === package.json の版」を確かめる検査を置くと、元のツリーでは通るのに、予行では `ok: false` になることをテストで確かめる（対照として、同じ確認を「同じリリースか」で書けば通る）。実際のリポジトリに一時的にテストを足す手順は、`tests/` を変えられない実装の担当には行えないため、自動のテストで置き換え、WORKLOG に記録する |
| B6 | `ci.yml` にジョブ `db-release-rehearsal` を追加。アクションは SHA 固定、permissions は contents: read | ジョブ ID が `db-release-rehearsal`。`actions/checkout` と `actions/setup-node` を使い、`npm ci` の後に `node scripts/ci/rehearse-db-release.mjs` を実行する。ci.yml のすべての `uses:` が 40 桁の commit SHA。ワークフロー全体の permissions は `contents: read` だけで、ジョブで指定するなら `contents: read` だけ。ci.yml に書き込み権限が無い |
| B7 | `scripts/ci/check-size.mjs` を作り、build の後に実行する。上限は G7（advisory-db.json は 2 MB、dist 合計は 3 MB）。80% を超えたら警告、超えたら失敗 | `SIZE_LIMITS = { advisoryDb: 2 MiB, dist: 3 MiB }`、`WARN_RATIO = 0.8`。`classifySize(bytes, limit)` は `bytes > limit` で `'fail'`、`bytes > limit × 0.8` で `'warn'`、それ以外は `'ok'`（ちょうど 80%・ちょうど上限は「超えた」に当たらない）。dist は入れ子を含む全ファイルの合計。コマンドは警告なら終了コード 0 で `::warning`、失敗なら 1 で `::error` を出す。ci.yml では同じジョブの中で `npm run build` の後に実行する |
| B8 | 受け入れ条件 3「actionlint が通る」 | actionlint がインストールされている環境で、`actionlint ci.yml` の終了コードが 0。CI の実行環境（ubuntu-latest）には actionlint が無く、依存も足せないので、無い環境ではこのテストだけ skip する（夜間の実行環境には入っている） |

解釈で決めたこと（指示書に無い・曖昧な点）:

- **dataVersion の「進め方」**: 指示書は「進めて」だけなので、テストは「元より後の、YYYYMMDD として正しい日付」だけを求める。実装は「元の翌日（UTC の暦で）」を推奨する（実行日に依存せず決まるため）。今日の日付にする実装でも、元より後なら合格する。
- **MB の数え方**: 既存の `scripts/validate-advisories.mjs` の `MAX_FILE_SIZE_BYTES = 2 * 1024 * 1024`（2MB上限）に合わせ、1 MB = 1024 × 1024 バイトとする。DB の上限は同じ値であることもテストで確かめる。
- **dist や DB が無いとき**: build の後に実行する前提なので、測れないものは合格にせず失敗にする（安全側。build を忘れたときに素通りさせない）。
- **測る DB**: `src/detection/advisory-db.json`（同梱 DB の元のファイル）。dist の中では JS に埋め込まれるので、dist の合計で別に数える。
- **テストのコマンドの差し替え**: 全体の `npm test` をテストの中で走らせると時間がかかり、予行の中で予行のテストが再び走る入れ子にもなるので、`testCommand` と DB の場所（`advisoryDbPath`）を引数で差し替えられるようにする。合成のツリーでは DB を別名（`data/synthetic-advisory-db.json`）に置き、テストに同梱 DB のファイル名を書かない（T01 の test-hygiene に当たらないようにするため）。
- **テストに書いた合成の値**: 合成のツリーの版 `3.4.5` と dataVersion `20990101` は合成データで、同梱 DB や package.json の値ではない（AGENTS.md の「版・件数・日付・dataVersion を直接書かない」は実際の値への依存を禁じるもので、合成の入力には当たらないと解釈した）。
- **ジョブの permissions**: ワークフロー全体の `permissions: contents: read` を受け継げば足りるので、ジョブでの指定は任意とした（指定するなら `contents: read` だけ）。

## 実装の方針

### 新規 `scripts/ci/rehearse-db-release.mjs`（ESM。外部依存なし）

```js
/** 既定のテストのコマンド（[コマンド, ...引数]） */
export const DEFAULT_TEST_COMMAND = ['npm', 'test'];

/**
 * dataVersion（YYYYMMDD）を進めた値を返す。推奨: UTC の暦で翌日。
 * YYYYMMDD（数字 8 桁）でない値は例外を投げる。
 * @param {string} current
 * @returns {string}
 */
export function nextDataVersion(current) {}

/**
 * DB を複製し、dataVersion を nextDataVersion で進め、
 * integrity を { algorithm: 'sha256', target: 'libraries', digest: sha256(JSON.stringify(libraries)) } にしたものを返す。
 * 入力は変更しない。libraries とほかの項目（schemaVersion、minExtensionVersion など）はそのまま。
 * @param {object} db
 * @returns {object}
 */
export function bumpAdvisoryDb(db) {}

/**
 * DB だけのリリースの予行。
 * @param {{
 *   sourceDir?: string,        // 既定: リポジトリ直下（このファイルの 2 階層上）
 *   testCommand?: string[],    // 既定: DEFAULT_TEST_COMMAND。一時コピーを cwd にして実行する
 *   advisoryDbPath?: string,   // ツリーの直下からの相対パス。既定: 'src/detection/advisory-db.json'
 *   keepWorkDir?: boolean,     // 既定 false（終了後に一時コピーを消す。成功・失敗とも）
 * }} [options]
 * @returns {Promise<{
 *   ok: boolean,                     // 採番・DB の更新・テストのすべてが成功したら true
 *   exitCode: number | null,         // テストのコマンドの終了コード（テストまで進まなかったら null か 0 以外）
 *   workDir: string,                 // 一時コピーの場所（keepWorkDir が false なら、返す時点で消えている）
 *   previousManifestVersion: string, // コピー前の manifest の版
 *   manifestVersion: string,         // 採番後の manifest の版
 *   previousDataVersion: string,
 *   dataVersion: string,
 * }>}
 */
export async function rehearseDbRelease(options) {}
```

処理の順番:

1. `fs.mkdtempSync(path.join(os.tmpdir(), 'db-release-rehearsal-'))` で一時ディレクトリを作る（元のツリーの外）。
2. コピー: `sourceDir` が Git の作業ツリーの最上位なら `git ls-files -z --cached --others --exclude-standard` の一覧（ディスクに無いもの＝削除済みは飛ばす）をコピーする。Git の作業ツリーでない・git が使えないときは、全体を再帰でコピーし、少なくとも `.git`・`node_modules`・`dist`・`reports` を除く（予行のコピーの中で予行のテストが走るとき、コピーは Git の作業ツリーではない）。
3. `sourceDir/node_modules` があれば、コピーに `node_modules` のシンボリックリンク（`fs.symlinkSync(realpath, ..., 'dir')`）を作る。無ければ何もしない。
4. コピーの中の `scripts/advisories/bump-db-revision.mjs` を `process.execPath` で、cwd をコピーにして実行する。**元のツリーのスクリプトを実行しない**（`scripts/advisories/lib/util.mjs` の `ROOT_DIR` はスクリプトの場所から決まるので、元のスクリプトを実行すると元の manifest が書き換わる）。子の環境から `GITHUB_OUTPUT` を外す（CI のジョブの出力に `version=…` を書き足さないため）。終了コードが 0 以外なら `ok: false` で終える（例外にしてもよい。テストはどちらも受け付ける）。
5. コピーの `advisoryDbPath` を読み、`bumpAdvisoryDb` を通して書き戻す（書き方は `JSON.stringify(db, null, 2) + '\n'`。scripts/advisories/lib/util.mjs の `stableStringify` と同じ）。
6. `testCommand` を cwd = コピーで実行する（`spawnSync`、`stdio: 'inherit'` でよい）。`npm` を使うので、Windows を考えるなら `shell` の扱いに注意（CI は ubuntu なので必須ではない）。
7. `keepWorkDir` が false なら、成功・失敗とも `fs.rmSync(workDir, { recursive: true, force: true })` で消す（シンボリックリンクの先の `node_modules` は消えない）。
8. コマンドとして実行したとき（`import.meta.url === pathToFileURL(process.argv[1]).href`。既存の scripts と同じ書き方）は、既定の引数で予行し、結果を日本語で表示して `ok` なら終了コード 0、そうでなければ 1。**import しただけでは予行を始めない**（テストが import するため）。

### 新規 `scripts/ci/check-size.mjs`（ESM。外部依存なし）

```js
export const SIZE_LIMITS = { advisoryDb: 2 * 1024 * 1024, dist: 3 * 1024 * 1024 }; // G7
export const WARN_RATIO = 0.8;

/** @returns {'ok' | 'warn' | 'fail'}  bytes > limit → fail、bytes > limit * WARN_RATIO → warn、それ以外 ok */
export function classifySize(bytes, limit) {}

/** ディレクトリ以下（入れ子を含む）の全ファイルの大きさの合計（バイト） */
export function measureDirBytes(dir) {}

/**
 * @param {{ advisoryDbPath?: string, distDir?: string }} [options]  既定: リポジトリの src/detection/advisory-db.json と dist/
 * @returns {{ ok: boolean, results: Array<{ target: 'advisoryDb' | 'dist', path: string, bytes: number | null, limit: number, level: 'ok' | 'warn' | 'fail' }> }}
 *   ファイル・ディレクトリが無いものは bytes: null, level: 'fail'。ok は fail が 1 件も無いこと
 */
export function checkSizes(options) {}
```

コマンド: `node scripts/ci/check-size.mjs [--db <path>] [--dist <dir>]`。各対象の大きさと上限を表示する。warn は `::warning::…`（終了コード 0）、fail は `::error::…`（終了コード 1）を標準出力か標準エラーに出す。ok のときは `::warning`・`::error` を出さない。

### `.github/workflows/ci.yml`（T02 で変更を許可）

- ジョブ `verify` の「Build Extension (Vite)」の直後に、手順 `node scripts/ci/check-size.mjs` を足す（同じジョブの中で build より後）。
- ジョブ `db-release-rehearsal` を足す。例:

```yaml
  db-release-rehearsal:
    name: DB-only release rehearsal
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - name: Checkout repository
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Setup Node.js 22 (LTS)
        uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 22
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Rehearse DB-only release (bump DB revision -> npm test in a temp copy)
        run: node scripts/ci/rehearse-db-release.mjs
```

- アクションの SHA は既存の verify と同じものを使う（新しいアクションを足さない）。ワークフロー全体の `permissions: contents: read` は変えない。`write` の権限を足さない。
- CI-01 Guard の手順・`on:`・`concurrency:` は変えない。

## 外部の事実

| 事実 | 一次資料 | 確認日 |
| --- | --- | --- |
| Chrome の manifest の version は 1〜4 個の 0〜65535 の整数（DB だけのリリースが 4 つ目の番号を使う根拠。既存の bump-db-revision.mjs のコメントにある資料を再掲） | https://developer.chrome.com/docs/extensions/reference/manifest/version | 2026-11-11（このタスクでは判定に新しく使っていない。既存の採番をそのまま使う） |
| GitHub Actions のワークフローコマンド `::warning file=…::{message}` と `::error file=…::{message}` は、ログにメッセージを出し、注記（annotation）を作る。`::error` を出すだけでは手順は失敗しない（`core.setFailed` が「`::error` と `exit 1`」の近道と書かれている）ので、失敗は終了コード 1 で別に伝える | https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands | 2026-11-11 |

## 実装の担当への注意

- **`tests/` と設計メモは変更しない**。テストが仕様と合わないと考えたら `.agy-out/result.json` に `needsTestChange: true` と理由を書いて終える。
- 変更してよいのは `scripts/ci/`（新規）と `.github/workflows/ci.yml` だけ。`scripts/advisories/`（bump-db-revision.mjs を含む）、`src/detection/advisory-db.json`、`data/advisories/` は変更禁止（§2.3）。予行は、これらを**コピーの中で**書き換えるだけにする。
- **元のツリーの `scripts/advisories/bump-db-revision.mjs` を実行しない**。`scripts/advisories/lib/util.mjs` の `ROOT_DIR` はスクリプトの場所から決まるので、元のスクリプトを実行すると元の `public/manifest.json` が書き換わる。必ずコピーの中のスクリプトを、cwd をコピーにして実行する。
- 予行のコピーの中でも `npm test` が走り、そこで `tests/ci-db-release-rehearsal.test.ts` も実行される。そのときのツリーは Git の作業ツリーではないので、コピーの方法は git が使えないときの方法（除外リスト付きの再帰コピー）でも動くこと。`node_modules` がシンボリックリンクのときは、その中をたどってコピーしない。
- 一時コピーを元のツリーの中（`.tmp/` など）に作らない。Vitest や test-hygiene がコピーの中のテストを拾ってしまう。
- `import` しただけで予行やサイズの確認を始めない（テストが関数を import する）。既存の scripts と同じく `import.meta.url === pathToFileURL(process.argv[1]).href` のときだけ main を実行する。
- テストは同梱 DB のファイル名を書かないよう、合成のツリーでは `advisoryDbPath` で別名の DB を渡す。`advisoryDbPath` はツリーの直下からの相対パスとして扱う（絶対パスにしない）。
- `testCommand` の終了コードを `exitCode` にそのまま返す（テストは 3 を返すコマンドで `exitCode === 3` を確かめる）。
- check-size の「超えたら」は `>`（ちょうど 80%・ちょうど上限は超えていない）。MB は 1024 × 1024。dist が無い・DB が無いときは失敗にする。
- ci.yml では、既存の verify の手順の順番を変えない（check-size は build の直後に足す）。新しいジョブも、アクションは既存と同じ SHA を使い、`persist-credentials: false` を付ける。`permissions` に write を足さない。
- actionlint のテストは、actionlint がある環境（夜間の実行環境）で実行される。現在の ci.yml は actionlint を通ることを確かめ済み。`run:` のシェルにも shellcheck の指摘が出ないように書く（変数は引用符で囲む）。
- 受け入れ条件 2（旧来の書き方のテストを一時的に足すと予行が失敗する）は、tests/ を変えられないため、合成のツリーの自動テストで確かめる。実際のリポジトリで手で試す場合は人が行う。
