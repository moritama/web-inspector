# T04 設計メモ — 対応表の週次の突き合わせ

## 目的

人が編集する対応表（`data/advisories/distro-map.json`、H3）が古くならないよう、週次の DB 更新ワークフローで Ubuntu（Launchpad の API）と Debian（sources.debian.org の API）の「各リリースで現在公開されている版」と突き合わせ、対応表に無い上流版を「ずれ」として報告する。対応表は書き換えない。結果は `build-report.json` の `distroMapDrift` に入れ、ボット PR の本文に「対応表のずれ」の節として載せる。

## 仕様の解釈

受け入れ条件と §5.4 を、テストで確かめられる形に言い直す。

| # | 指示書 | テストで確かめる形 |
| --- | --- | --- |
| A1 | 対応表に無い版が公開されている応答で「ずれ」 | 偽の応答で、対応表の項目（リリース × ソースパッケージ）の公開中の版の上流版のうち、`upstreamVersions` に無いものがあれば、その項目の `status` が `'drift'`、`unlistedUpstreamVersions` にその上流版が入り、全体の `status` も `'drift'` |
| A2 | 一致する応答で「なし」 | 公開中の版の上流版がすべて `upstreamVersions` にあれば、項目の `status` が `'none'`、`unlistedUpstreamVersions` が `[]`、全体も `'none'` |
| A3 | 取得失敗で「未確認」 | HTTP エラー・ネットワークのエラー・JSON でない応答・形の違う応答・そのリリースの公開中の版が 1 件も無い応答で、項目の `status` が `'unchecked'`（理由 `error` 付き）。例外を投げず、ほかの項目は続ける |
| A4 | 対応表のファイルを書き換えない（テストで確認） | `runDistroMapCheck` を「ずれ」の応答で実行しても、対応表のファイルの中身と更新時刻が変わらない。CLI を一時ディレクトリで実行しても対応表のバイト列が変わらない。`checkDistroMap` に渡した対応表のオブジェクトも変えない |
| A5 | 結果を build-report.json の `distroMapDrift` に入れる | `runDistroMapCheck` が `build-report.json` を読み、ほかの項目を残したまま `distroMapDrift` だけを今回の結果で置き換えて書く |
| A6 | pr-plan.mjs がボット PR の本文に「対応表のずれ」の節を作る | `planPullRequest({ …, distroMapDrift })` の `body` に「対応表のずれ」を含む節。ずれ → リリース・ソースパッケージ・上流版を載せる、なし → 「なし」、未確認 → 「未確認」で「なし」と書かない。渡さなければ従来どおり。CLI は `--build-report <path>` で読む |
| A7 | ずれがあっても PR は止めない | `distroMapDrift` を渡しても `shouldCreatePr`・`labels`・`shouldAutoMerge`・`shouldFailJob` は渡さないときと同じ |
| A8 | API が失敗したら「未確認」、ワークフローは失敗させない。`continue-on-error` を使わず、スクリプトが 0 で終わる | CLI（`globalThis.fetch` が全部 404 を返す状態）が終了コード 0 で終わり、`distroMapDrift.status` が `'unchecked'`。ワークフローに `continue-on-error` が無く、突き合わせのコマンドを `|| true` で包まない |
| A9 | advisory-db-update.yml にステップを足す。新しいワークフローは作らない | `node scripts/advisories/check-distro-map.mjs` を実行するステップが build-db の後・pr-plan の前にあり、pr-plan に `--build-report data/advisories/build-report.json` を渡す。check-distro-map を実行するワークフローは advisory-db-update.yml だけ。週次の cron はそのまま |
| A10 | actionlint が通る。新しいアクションは SHA 固定 | actionlint がある環境で advisory-db-update.yml にエラーが無い。`uses:` はすべて 40 桁の SHA |

指示書が曖昧な点と、どう解釈したか（安全側：断定しない・警告を増やしすぎない）。

1. **「現在の版」の範囲。** Ubuntu は Launchpad の `getPublishedSources` で `status` が `Published`、`pocket` が `Release`・`Updates`・`Security` のもの。`Proposed`（検証中）と `Backports` は数えない（T02 で対応表を作ったときの基準「Proposed とリリース前だけの版は除く」と同じ。Backports は H9 と同じく対象外）。`Superseded`・`Deleted`・`Pending`・`Obsolete` も数えない。Debian は sources.debian.org の `versions[]` のうち、`suites` にそのリリースのコード名（例 `bookworm`）、`<コード名>-updates`、`<コード名>-security` のどれかを含むもの。`-proposed-updates` と `-backports` は数えない。ほかのリリース（`sid`・`forky` など）の版は数えない。
2. **上流版の取り出し。** パッケージの版（dpkg の書式 `[epoch:]upstream[-revision]`）から、epoch（最初の `:` まで）を外し、最後の `-` から後（revision）を外し、残りの先頭の `/^\d+(?:\.\d+)+[a-z]?/` を上流版とする。これで `1.1.1-1ubuntu2.1~18.04.23` → `1.1.1`、`1:2.4.59+dfsg-1~deb12u1` → `2.4.59`、`1.1.0g-2ubuntu4` → `1.1.0g` になり、対応表の `upstreamVersions` の形（T02 の `/^\d+(?:\.\d+)+[a-z]?$/`）と比べられる。取り出せない版は使わない。
3. **不正な版の扱い。** 応答の版が `/^[0-9A-Za-z.+~:-]+$/` に合わない（`<`・`>`・`` ` ``・`|`・空白などを含む）か 100 文字を超えるときは、その版を捨てる（結果にも PR の本文にも出さない）。外部の応答をそのまま Markdown に入れないため。
4. **「未確認」になる条件。** 取得の例外（HTTP エラー・ネットワーク・JSON でない）、応答の形が違う（Launchpad の `entries` が配列でない、Debian の `versions` が配列でない、Debian の `{"error":404}`）、使える公開中の版が 1 件も無い（「なし」と断定しない）。`codename` が無い項目も「未確認」。
5. **全体の結果。** ずれが 1 件でもあれば `'drift'`。ずれが無く未確認が 1 件でもあれば `'unchecked'`（一部しか確かめていないのに「なし」と断定しない）。すべて一致したときだけ `'none'`。対象の項目が 0 件のときも `'unchecked'`。
6. **RHEL 系。** §5.4 は Ubuntu と Debian の API だけを挙げている（H1 で RHEL 系は第2段階まで）。`family` が `ubuntu`・`debian` 以外の項目は問い合わせず、結果の `items` にも件数にも入れない（入れると毎週「未確認」になり、警告が増えすぎる）。
7. **ページ送り。** Launchpad の応答は既定でページに分かれ、`next_collection_link` が付く（外部の事実）。`status=Published` を付けても念のため次のページを追う。追うのは `api.launchpad.net` の URL だけで、最大 20 ページ。
8. **PR の本文。** `distroMapDrift` があれば、状態にかかわらず節を作る（「なし」も書く。毎週確かめたことが PR で分かる）。ずれと未確認の項目だけを並べ、一致した項目は件数だけにする。「なし」の語は全体が `'none'` のときだけ使う（件数の行では「一致」と書く）。`classification` が `none` で PR を作らない週は、本文も作られない（突き合わせの結果はワークフローの成果物の build-report.json に残る）。
9. **自動マージ。** 「ずれがあっても PR は止めない」に従い、ずれは自動マージの条件に影響させない（ずれは DB の中身に影響しない。対応表を直すのは人）。
10. **終了コード。** CLI は、API の失敗だけでなく、対応表が読めない・build-report.json が壊れているなど想定外のことがあっても「未確認」を記録して 0 で終わる（ジョブを止めない）。ただし、ワークフロー側で `|| true` は使わない（スクリプトの約束として 0 で終わる）。

## 実装の方針

変更してよい場所（K2.2）: `scripts/advisories/`、`.github/workflows/advisory-db-update.yml`。`data/advisories/distro-map.json` と `build-report.json` は変更しない。

### 1. 新規 `scripts/advisories/check-distro-map.mjs`

テストが import する公開 API（名前と形をこのまま）。

```js
/**
 * 対応表と API の突き合わせ（ネットワークには fetchJson を通してだけ出る）
 * @param {{ distroMap: { entries: object[] }, fetchJson: (url: string) => Promise<any>, now?: Date }} params
 * @returns {Promise<DistroMapDrift>}
 */
export async function checkDistroMap({ distroMap, fetchJson, now = new Date() })

/**
 * 対応表のファイルを読み、突き合わせ、build-report.json の distroMapDrift を書く。例外を投げない（失敗は 'unchecked'）
 * 対応表のファイルには書き込まない。
 * @param {{ mapPath?: string, reportPath?: string, fetchJson: Function, now?: Date, log?: (msg: string) => void }} params
 *   mapPath の既定は PATHS.distroMap、reportPath の既定は PATHS.buildReport
 * @returns {Promise<DistroMapDrift>}
 */
export async function runDistroMapCheck({ mapPath, reportPath, fetchJson, now, log })
```

戻り値 `DistroMapDrift`（build-report.json の `distroMapDrift` にそのまま入る。JSON にそのまま書ける値だけ）:

```js
{
  checkedAt: now.toISOString(),
  status: 'drift' | 'none' | 'unchecked',          // 解釈 5
  counts: { drift: number, none: number, unchecked: number },  // items の status の数
  items: [
    {
      family: 'ubuntu' | 'debian',
      release: 'ubuntu:22.04',          // 対応表の値
      codename: 'jammy',                // 対応表の値
      product: 'nginx',                 // 対応表の値
      sourcePackage: 'nginx',           // 対応表の値
      status: 'drift' | 'none' | 'unchecked',
      mapUpstreamVersions: string[],    // 対応表の upstreamVersions の写し
      publishedVersions: string[],      // 数えた公開中のパッケージの版（解釈 3 を通ったもの。重複なし）。unchecked は []
      unlistedUpstreamVersions: string[], // 対応表に無い上流版（重複なし）。none・unchecked は []
      sourceUrl: string,                // 問い合わせた API の URL（最初のページ）
      error?: string,                   // unchecked のときだけ。空でない短い文（200 文字まで。外部の応答本文をそのまま入れない）
    },
  ],
}
// runDistroMapCheck で対応表を読めなかったときは items: [] と error を付けた 'unchecked'
```

- 対象は `family` が `ubuntu`・`debian` の項目だけ（解釈 6）。対応表の順に並べる。
- **Ubuntu**: URL は次の形（`URL`・`searchParams` で組み立てる）。`distro_series` は `https://api.launchpad.net/1.0/ubuntu/<codename>`。
  `https://api.launchpad.net/1.0/ubuntu/+archive/primary?ws.op=getPublishedSources&source_name=<sourcePackage>&exact_match=true&distro_series=https://api.launchpad.net/1.0/ubuntu/<codename>&status=Published`
  応答の `entries[]` のうち、`status === 'Published'` かつ `pocket` が `Release`・`Updates`・`Security` で、`source_package_name === sourcePackage` のものの `source_package_version` を数える（`status=Published` を付けても、応答の側でも絞る）。`next_collection_link` が `api.launchpad.net` の URL なら続けて取得（最大 20 ページ）。
- **Debian**: URL は `https://sources.debian.org/api/src/<sourcePackage>/`。応答に `error` があるか `versions` が配列でなければ「未確認」。`versions[]` のうち `suites` に `<codename>`・`<codename>-updates`・`<codename>-security` のどれかを含むものの `version` を数える。同じソースパッケージは 1 回の取得を使い回してよい（テストはどちらでも通る）。
- 上流版の取り出しは解釈 2、不正な版は解釈 3。
- 各項目の取得の例外は項目ごとに捕まえ、「未確認」にして次へ進む。

CLI（`node scripts/advisories/check-distro-map.mjs`、引数なし）:

- `runDistroMapCheck({ fetchJson: createFetchJson({ retries: 2, log }), log: console.log })`（`lib/http.mjs` の `createFetchJson` を使う。`fetchImpl` は渡さない＝`globalThis.fetch`。`minIntervalMs` は付けない）。終わったら結果の要約（全体の状態と件数）を出力し、**必ず `process.exit(0)`**（例外も捕まえて 0）。
- ずれ・未確認があれば `::warning::` の行を出してよい（任意）。
- 入口の判定は build-db と同じく `fs.realpathSync(process.argv[1])` と `import.meta.url` を比べる（テストは実パスを渡すが、どちらでも動くように）。
- 対応表のファイルには書き込まない（`fs.writeFileSync` するのは `reportPath` だけ）。`reportPath` のファイルが無ければ `{ distroMapDrift }` だけのファイルを作る。読めない（壊れている）ときも同じ。書き出しは `lib/util.mjs` の `stableStringify`（または `writeJson`）。

### 2. `scripts/advisories/pr-plan.mjs`

- `planPullRequest(params)` に任意の引数 `distroMapDrift`（上の形。既定 `null`）を足す。`classification !== 'none'` のとき、`renderPrBody(...)` で作った本文の後に「対応表のずれ」の節を足す。`distroMapDrift` が null・オブジェクトでなければ本文は従来と同じ（1 文字も変えない）。
- 節を作る関数を export してよい（例 `renderDistroMapDriftSection(drift)`。テストは直接使わない）。
- 節の形（文言の例。テストが確かめるのは「対応表のずれ」の見出し・リリース・ソースパッケージ・上流版・「なし」「未確認」の語だけ）:

```md
### 対応表のずれ (distro-map.json)

結果: **ずれ**（ずれ 1 件・一致 1 件・未確認 1 件）

- ずれ: `ubuntu:22.04` nginx（nginx）: 対応表に無い上流版 `1.99.9`
- 未確認: `debian:13` php（php8.4）

対応表は自動では書き換えません。一次資料で確かめてから人が更新してください。
```

  - 結果の語は `drift` → 「ずれ」、`none` → 「なし」、それ以外 → 「未確認」。**「なし」の語は全体が `none` のときだけ使う**（件数の行は「一致」と書く。未確認の節に「なし」を書かない）。
  - 項目はずれと未確認だけを並べる（一致は件数だけ）。値は Markdown に入れる前に `[^0-9A-Za-z.+~:_-]` を取り除く（build-report.json は CI の中で作られるが、念のため）。
- `shouldCreatePr`・`labels`・`removeLabels`・`shouldAutoMerge`・`shouldFailJob` の計算は変えない（解釈 9）。
- CLI に `--build-report <path>` を足す。ファイルがあれば JSON を読み、`distroMapDrift` を `planPullRequest` に渡す。ファイルが無い・壊れている・`distroMapDrift` が無いときは渡さない（失敗にしない）。

### 3. `.github/workflows/advisory-db-update.yml`

- 「Validate advisory DB」（`node scripts/validate-advisories.mjs`）の直後に、次のステップを足す（build-db が build-report.json を作り直した後で、pr-plan の前）。`if:` は付けない（毎週実行し、結果は成果物の build-report.json に残る）。`continue-on-error` と `|| true` は使わない。

```yaml
      # 対応表 (distro-map.json) と Launchpad / sources.debian.org の API の突き合わせ (H3)。
      # 取得に失敗しても「未確認」を build-report.json に記録して 0 で終わる。対応表は書き換えない
      - name: Check distro map drift
        run: node scripts/advisories/check-distro-map.mjs
```

- 「Plan pull request」の `pr-plan.mjs` の引数に `--build-report data/advisories/build-report.json \` を足す（`--test-log` の行の後など）。
- 新しいアクションは使わない（必要なら 40 桁の SHA で固定）。ほかのステップ・cron・permissions は変えない。

## 実装の担当への注意

- **対応表（`data/advisories/distro-map.json`）は変更禁止**（T04 で変更してよいのは `scripts/advisories/` と `advisory-db-update.yml` だけ）。スクリプトも対応表に書き込まない。`build-report.json` も手で編集しない（build-db とこのスクリプトの実行結果だけが書く。夜のスクリプトの build-db は `distroMapDrift` の無い build-report.json を書くが、それでよい）。
- **ネットワークに出るのは CLI だけ。** テストは `checkDistroMap`・`runDistroMapCheck` に偽の `fetchJson` を渡し、CLI のテストは `node --import <preload>` で `globalThis.fetch` を「HTTP 404 を返す偽物」に差し替える。CLI が `globalThis.fetch` 以外（`node:https` など）で取得すると、テストが実際のネットワークに出てしまう。必ず `createFetchJson()`（既定で `globalThis.fetch`）を使う。`minIntervalMs` を付けるとテストが遅くなるので付けない。
- CLI のテストは、`scripts/advisories/lib/` のすべてのファイルと `check-distro-map.mjs` と `distro-map.json` だけを一時ディレクトリにコピーして動かす。`check-distro-map.mjs` が import してよいのは `./lib/` の中のファイルと Node.js の標準モジュールだけ（`build-db.mjs` などを import しない）。パスは `lib/util.mjs` の `PATHS.distroMap`・`PATHS.buildReport` を使う。
- エージェントは CLI を実行しない（外部にアクセスするため。夜間ルール）。
- `planPullRequest` の既存の戻り値の項目と、`distroMapDrift` が無いときの本文は 1 文字も変えない（既存の pr-plan のテスト）。
- 「なし」の語は、全体が `none` のときの結果の語だけに使う。件数の行は「一致」と書く（未確認の節に「なし」があるとテストが落ちる。H4 の考え方：確かめていないのに無いと書かない）。
- ワークフローに `continue-on-error` を使わない。突き合わせのコマンドを `|| true`・`|| :`・`|| exit 0` で包まない。`set +e` も不要（スクリプトが 0 で終わる）。
- actionlint は手元に入っていれば `actionlint .github/workflows/advisory-db-update.yml` で確かめられる（テストも、入っている環境では実行する）。
- 外部の値は上の「外部の事実」の表にあるものだけを使う。表に無い API の項目（`date_published` で並べ替えるなど）を推測で使わない。
