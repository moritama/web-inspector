# T06 設計メモ — NEW-03a ヘッダーの追加評価

## 目的

取得だけしていた COOP・COEP・CORP と、「未設定」しか見ていなかった Permissions-Policy を評価する。旧式の X-XSS-Protection と、内部情報が見えるヘッダー（X-AspNetMvc-Version、Server-Timing）も指摘する。新しい指摘は最大 LOW（G4）。ヘッダーが未観測なら unknown にする（SPEC-01）。

### 各 ID の判定（解釈と理由）

値の比較の前に、前後の空白を取り除く。ヘッダーが複数行あるときは、既存の `getHeader` と同じく `', '` でつないだ 1 つの値として扱う（RFC 9651 §4.2 と同じ扱い）。

- **SEC-COOP-01**（info / info）: 次のどれかのとき出す。
  - ヘッダーが無い
  - 値（`;` より前の部分。`report-to` などの引数は無視する）が `unsafe-none`
  - 値が仕様の値（`unsafe-none`・`same-origin-allow-popups`・`same-origin`・`noopener-allow-popups`）のどれでもない。仕様では、無効な値のヘッダーはブラウザが無視し、既定の `unsafe-none` になるため（外部の事実 1）。指摘は info だけなので、警告は増えない。
  - 出さないのは `same-origin`・`same-origin-allow-popups`・`noopener-allow-popups`（引数があってもよい）。
  - http のページでは、ブラウザは COOP を使わない（外部の事実 1）。ただし指示書の表は「COOP がない」とだけ書いているので、scheme で分けない。テストは https だけで確かめる。
- **SEC-COEP-01**（info / info）: ヘッダーがあり、値（`;` より前）が `unsafe-none`・`require-corp`・`credentialless` のどれでもないとき。無いときは何も出さない（COEP を勧めない）。`unsafe-none` は仕様にある値なので出さない。
- **SEC-CORP-01**（info / info）: ヘッダーがあり、値が `same-origin`・`same-site`・`cross-origin` のどれとも一致しないとき。CORP の ABNF は大文字・小文字を区別し、引数を持たないので、`SAME-ORIGIN` や `same-origin; foo` も「仕様にない値」として出す（外部の事実 2）。無いときは出さない。
- **SEC-XXSS-01**（info / info）: ヘッダーがあり、値の `;` より前の部分が `1` のとき（`1`、`1; mode=block`、`1;mode=block`、`1; report=…`）。`0` と、ヘッダーが無いときは出さない。それ以外の値（解釈できない値）は出さない（安全側。表にない）。
- **SEC-PERM-02**（warning / low）: Permissions-Policy を Structured Field の Dictionary として解析でき、強い権限のどれかの値が、トークン `*`（`camera=*`）か、`*` を含む Inner List（`camera=(*)`）のとき。仕様では、どちらも「すべてのオリジンに許可」になる（外部の事実 3）。
  - 強い権限は、指示書に名前がある **camera・microphone・geolocation・payment・usb の 5 つだけ**にする。「など」を広げると警告が増えるため（安全側）。`fullscreen=*` などは出さない。
  - 強い権限を複数 `*` にしていても、**1 件にまとめる**。observed か description に、該当する権限名をすべて書く（判定根拠）。
  - 構文が解釈できないときは出さない（ブラウザはヘッダー全体を無視するので、`*` の許可を断定できない）。
  - 項目名は既存どおり `Permissions-Policy`（§8.1 の項目名の統一。`scripts/report-lint.mjs` が `SEC-PERM-` の項目名を検査している）。
- **SEC-PERM-03**（info / info）: Permissions-Policy があり、RFC 9651 の Dictionary として解析できないとき（外部の事実 4）。例: Feature-Policy の書き方 `camera 'none'; microphone 'none'`、閉じていない `geolocation=(self`、空の要素 `geolocation=(), , camera=()`、末尾のカンマ `geolocation=(),`。項目名は `Permissions-Policy`。
  - 構文は正しいが意味が誤っている値（例: 引用符のないオリジン、未知の権限名）は、このタスクでは指摘しない（テストしない）。
  - ヘッダーがあるときは、従来どおり SEC-PERM-01（未設定）を出さない。
- **SEC-DISC-04**（warning / low）: `X-AspNetMvc-Version` があるとき。category は既存の SEC-DISC-* と同じ `information-disclosure`。observed に値を入れる。
- **SEC-DISC-05**（info / info）: `Server-Timing` があるとき。category は `information-disclosure`。

### 新しい ID の数

新しい ID は、1 回の `checkHttpHeaders` で同じ ID が 2 件以上出ないようにする（テストで確かめる）。

### テストでは問わないこと（実装に任せる）

- 文言の一字一句、項目名（SEC-PERM-* を除く）、referenceUrls の中身、結果の配列の順番
- COOP・COEP の値を大文字・小文字を区別して比べるか（仕様のトークンは区別する。区別する実装を推奨）
- 合格の項目（例: SEC-COOP-00 pass）を作るかどうか。作る場合は新しい ID と同じ接頭辞にし、重大度は info にする
- http のページでの扱い（上のとおり、scheme で分けないことを推奨）

## 実装の方針

1. **`src/security/headers.ts`**
   - `SECURITY_HEADER_NAMES` に `'x-xss-protection'`、`'server-timing'`、`'x-aspnetmvc-version'` を足す（G5。`ALLOWED_RESPONSE_HEADERS` はここから作られる）。COOP・COEP・CORP は既にある。
   - `checkHttpHeaders(headers, url, isHttps, options?)` の引数と戻り値は変えない。上の判定で次の項目を追加する。
     | checkId | category | 推奨の name |
     | --- | --- | --- |
     | SEC-COOP-01 | `http-headers` | `Cross-Origin-Opener-Policy (COOP)` |
     | SEC-COEP-01 | `http-headers` | `Cross-Origin-Embedder-Policy (COEP)` |
     | SEC-CORP-01 | `http-headers` | `Cross-Origin-Resource-Policy (CORP)` |
     | SEC-XXSS-01 | `http-headers` | `X-XSS-Protection` |

     | SEC-DISC-04 | `information-disclosure` | `バックエンド技術情報露出 (X-AspNetMvc-Version)` |
     | SEC-DISC-05 | `information-disclosure` | `内部処理情報の露出 (Server-Timing)` |
   - Permissions-Policy の解析は、RFC 9651 §4.2.2 の Dictionary の解析を、このファイルの中の小さな関数として書く（依存パッケージを足さない）。推奨の形:
     ```ts
     /** Permissions-Policy の値を RFC 9651 の Dictionary として解析する。解析できなければ null */
     export function parsePermissionsPolicy(value: string): Map<string, PermissionsPolicyAllowlist> | null;
     export interface PermissionsPolicyAllowlist {
       /** トークン * か、* を含む Inner List */
       all: boolean;
       /** 値に含まれていた項目（self や "https://…" など。表示用） */
       items: string[];
     }
     ```
     テストはこの関数を直接は呼ばない（名前と型は推奨。`checkHttpHeaders` の結果で確かめる）。解析で必要なのは: key（lcalpha か `*` で始まり、lcalpha・数字・`_`・`-`・`.`・`*` が続く）、`=` が無ければ Boolean true、値はトークン・文字列・数値・Inner List、引数（`;key=value`）、要素の間の OWS と `,`、末尾のカンマは失敗、Inner List の `)` が無ければ失敗。
   - 推奨文（recommendation）の方針: COOP は `same-origin`（ポップアップとの連携が必要なら `same-origin-allow-popups`）を検討。COEP は「値を `require-corp` か `credentialless` に直すか、使わないならヘッダーを削除」。**COEP の設定を勧めない**。X-XSS-Protection は「`0` にするか削除し、CSP を使う」。Server-Timing は「本番では内部の処理名や時間を出さない」。X-AspNetMvc-Version は「`MvcHandler.DisableMvcResponseHeader = true` などで削除」。
   - observed に入れる値は、レスポンスヘッダーそのもの。長い Server-Timing などは 200 文字程度で切ってよい（任意）。

5. **`PRIVACY_POLICY.md`**: 取得するヘッダーに x-xss-protection・server-timing・x-aspnetmvc-version を足すなら、その記述を合わせる（G5。文面は人が承認するので、変更点を WORKLOG に書く）。テストはしない。

## 外部の事実

1. **COOP・COEP の値と、無効な値の扱い**: COOP の値は `unsafe-none`・`same-origin-allow-popups`・`same-origin`・`same-origin-plus-COEP`（ヘッダーでは送れない。`same-origin` と COEP の組み合わせで決まる）・`noopener-allow-popups`。ヘッダーは引数（`report-to`）つきのトークンの Structured Header で、無効な値は無視されて `unsafe-none` になる。非セキュアコンテキストでは既定の `unsafe-none` になる。COEP の値は `unsafe-none`・`require-corp`・`credentialless`。トークンとして解析できない値は `unsafe-none` になる（fail open）。
   - https://html.spec.whatwg.org/multipage/browsers.html#cross-origin-opener-policies 、 https://html.spec.whatwg.org/multipage/browsers.html#coep （2026-11-12 確認）
2. **CORP の値**: ABNF は `Cross-Origin-Resource-Policy = %s"same-origin" / %s"same-site" / %s"cross-origin" ; case-sensitive`。内部の検査の手順 3: 「If policy is neither `same-origin`, `same-site`, nor `cross-origin`, then set policy to null.」
   - https://fetch.spec.whatwg.org/#cross-origin-resource-policy-header （仕様の原文 https://raw.githubusercontent.com/whatwg/fetch/main/fetch.bs で原文を確認。2026-11-12）
3. **Permissions-Policy の `*`**: 「If value is the token `*`, or if value is a list which contains the token `*`, set allowlist to the special value `*`.」（Construct policy from dictionary and origin）。ヘッダーの解析結果が null なら、空の対応表を返す（Process response policy）。camera・microphone・geolocation・payment・usb は MDN の権限の一覧にある。
   - https://w3c.github.io/webappsec-permissions-policy/ （原文 https://raw.githubusercontent.com/w3c/webappsec-permissions-policy/main/index.bs で確認。2026-11-12）
   - https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy （2026-11-12）
4. **Structured Field の Dictionary の解析**: 要素の後は OWS を捨て、空なら終わり、次の文字が `,` でなければ失敗、`,` の後が空なら「trailing comma」で失敗。Inner List は `)` が見つからなければ失敗。key は lcalpha か `*` で始まる。複数の行は `,` でつないでから解析する。解析に失敗したら、そのフィールド全体を無視する。
   - https://www.rfc-editor.org/rfc/rfc9651.html §4.2、§4.2.1.2、§4.2.2、§4.2.3.3、§4.2.6（2026-11-12）
5. **X-XSS-Protection**: 非標準で非推奨。値は `0`・`1`・`1; mode=block`・`1; report=<uri>`。「X-XSS-Protection can create XSS vulnerabilities in otherwise safe websites」。OWASP は「Do not set this header or explicitly turn it off」で、CSP を使うよう勧めている。
   - https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-XSS-Protection 、 https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html （2026-11-12）
6. **X-AspNetMvc-Version**: OWASP は送信をやめるよう勧めている（`MvcHandler.DisableMvcResponseHeader = true;`）。COOP の推奨値は `same-origin`。
   - https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html （2026-11-12）
7. **Server-Timing**: OWASP の HTTP ヘッダーのチートシートには項目が無い（未確認）。指摘は指示書のとおり info にとどめる（「内部の処理名や時間が見える」は指示書の判断）。

## 実装の担当への注意

- **SEC-COOP-01 はヘッダーが無いページのほとんどで出る**（info）。要確認件数は増えないが、INFO の件数が 1 増える。既存のテストで INFO の件数を固定しているもの（`tests/security.test.ts` の `infoChecks.length >= 3` など）は、件数の下限だけを見ているので影響しない見込み。もし既存テストが落ちたら、テストは変えずに `.agy-out/result.json` に `needsTestChange: true` と理由を書く。
- **SPEC-01 の仕組みを壊さない**: 未観測のときの書き換えは `executeInspection` の既存のループで行われる。接頭辞を足すだけでよい。CSP の meta 由来の例外（`SEC-CSP-` だけ）を新しい ID に広げない。
- `tests/review-v1.6.5-acceptance.test.ts` の SPEC-01 のテストは `SEC-(HSTS|CSP|XFO|XCTO|REF|PERM)` が unknown か info であることを見ている。SEC-PERM-02 を未観測のときに warning にしない（接頭辞は既にあるので、既存の仕組みで unknown になる）。
- **Permissions-Policy の解析**: 正規表現で `=\*` を探すだけの実装にしない。`camera *; microphone *` のような解析できない値で SEC-PERM-02 を出してはいけない（テストあり）。`geolocation=(self "https://*.example.test")` の `*` は文字列の中なので「すべて許可」ではない（テストあり）。
- **既存の SEC-PERM-01 は変えない**（ヘッダーが無いときだけ出る）。
- **COEP の推奨文で COEP の設定を勧めない**（外部リソースを壊しやすいため。指示書）。
- `getHeader` は複数行を `', '` でつなぐ。COEP・CORP を複数行で送ると、つないだ値は仕様の値と一致しないので「仕様にない値」になる。これは仕様（ブラウザも無視する）と同じなので、そのままでよい（テストはしない）。
- `X-AspNetMvc-Version` は技術検出のルール（`src/detection/rules/backend.json`）でも使われている。ルール JSON は変えない。
- 新しい重大度は最大 low（G4）。`severity: 'medium'` 以上を新しい ID に使わない。
- observed や description にヘッダーの値を入れるとき、UI 側は既存どおり `escapeHtml()` を通している。新しく innerHTML に入れる箇所を作らない。
- `npm run spec:generate` は §8 を作り直さないので、仕様書の §8.3 に ID を手で書く。§3 のカタログ（自動生成）は手で編集しない。
