# T08 設計メモ — 版上げ 1.8.2 と文書

## 目的

指示書が曖昧な点と、どう解釈したか（安全側：断定しない・警告を増やしすぎない）。

1. **版の一致のテストを足さない。** v1.8.1 T08 と同じ理由（版を上げる前でも通るテストしか書けず、目標の版を見るには版を直書きする必要があり K3 に反する）。目標の版は総合チェック C12 と、スクリプトが package.json を一時的に 1.8.2 にして走らせる test-hygiene に任せる。
2. **ポップアップの案内を出す条件を直すこと。** 指示書は「Partial の理由に再読み込みの案内が出る（ポップアップ 450px で崩れない）」としているが、ポップアップには Partial の理由を出す場所が無く、ヘッダー未取得の案内は条件のキーが存在しないため出ない。受け入れ条件を満たすのに要る最小の変更として、既存の案内の条件を `coverage.details.unobservedPreScan`（v1.7.x から保存されているキー）に直す。新しい欄は作らない。案内の文は Partial の理由と同じ定数を使い、二重の文言管理をしない。DOM の収集だけが失敗した Partial などでは出さない（警告を増やしすぎない）。
3. **PRIVACY_POLICY は変えない。** v1.8.2 の変更で、外部への通信は増えない（拡張機能は追加のリクエストを送らない。K3）。権限も増えない（`chrome.cookies.getAllCookieStores` は既存の `cookies` 権限で使える。外部の事実）。D-3 で読む Cookie の保存先が「調べるタブの保存先」に変わるが、扱うのは今までどおり Cookie の名前と属性だけで、値は捨てる（第 2 章の記述のとおり）。E の出典の表示は個人のデータを扱わない。よって第 1〜4 章の記述は v1.8.2 でも正しい。`Last updated` も変えない。ただし、シークレットのタブを調べた結果も（spanning のため）通常の `chrome.storage.local` の履歴に保存されることはポリシーに書かれていない（v1.8.2 の前からの挙動）。書くかどうかは人が決める（WORKLOG の未解決と結果ファイルの note）。
4. **「制限事項」の場所。** §15 に 2 項目を足す。ダッシュボードとポップアップには制限事項の欄が無いので、欄を新しく作らない（指示に無い機能追加をしない）。仕様書の §8.5（調査完全性）にも案内と制限を 1〜2 文で書く（S1）。
5. **「ダッシュボードは通常ウィンドウで開く」の理由。** Chrome の文書では、spanning の拡張機能は自分のパッケージのページをシークレットのタブのメインフレームに読み込めない（外部の事実）。項目の文はこの事実の範囲で書き、「どこで開くか」「履歴がどこに入るか」などの文書に無いことを書き足さない。
6. **DETECTION_SPECIFICATION に書く範囲。** 指示書は「DETECTION_SPECIFICATION・MAINTENANCE_GUIDE」とだけ書いている。v1.8.2 の各タスクで判定と表示が変わったのに、仕様書と保守ガイドは起点から変わっていない（`git diff f0d67ab..HEAD` で確認）ので、変更ごとに要点を書くと解釈した。テストは語だけを見る（文面は人が承認する）。古くなった COOP・COEP の記述（「HTTP 接続のページでは」）は事実と違うので、陰性テストで置き換えを求める。
7. **`minExtensionVersion` と `MIN_EXTENSION_VERSION` は変えない。** DB のスキーマは 2.4 に上がったが、古い拡張機能（1.7.0 以降）も文字列の配列でない `sources` を読むだけで、照合は `sources` の形に依存しない（T06 の互換テスト）。保守ガイド §1.2 の「スキーマ互換性が変わらない更新では `1.7.0` のまま」に従う。指示書も変えるとしていない。
8. **`src/detection/advisory.ts` の `'1.8.3'` は変えない**（一般公開の版。版上げの対象ではない）。

### 3. ポップアップの案内（`src/popup/render.ts`・`src/popup/popup.ts`）

- `src/popup/render.ts` に追加:
  ```ts
  export function renderHeaderUnobservedNoticeHtml(coverage: InspectionCoverage | null | undefined): string
  ```
  - `coverage?.details?.unobservedPreScan === true` のときだけ HTML を返す。それ以外（undefined・null・false・DOM だけの Partial）は `''`
  - 返す HTML: 外側の要素は 1 つで、`class="notice-banner header-unobserved-banner"`（E2E が `.header-unobserved-banner` で探す）、`role="status"`。見た目は今の `popup.ts` の案内と同じインラインの style でよい（`word-break` を足すなら `overflow-wrap: anywhere`）。中身は `⚠️ <strong>HTTPヘッダー未取得</strong>: ${escapeHtml(HEADER_UNOBSERVED_PRESCAN_REASON)}`。インラインのイベントハンドラを使わない

## 外部の事実

| 事実・値 | 一次資料の URL | 確認した日付 |
| --- | --- | --- |
| manifest の `incognito` の既定は `"spanning"`（他に `"split"`・`"not_allowed"`）。spanning の拡張機能は「自分のパッケージのページをシークレットのタブのメインフレームに読み込めない」（"will not be able to load pages from its extension package into the main frame of an incognito tab"）。どこで開くかは書かれていない | https://developer.chrome.com/docs/extensions/reference/manifest/incognito | 2026-11-22 |
| `chrome.cookies` を使うには manifest に `"cookies"` 権限と、対象のホストの host permissions を宣言する。`getAllCookieStores()` は「Lists all existing cookie stores」で `CookieStore[]`（`id`: string、`tabIds`: number[]）を返す。シークレットのウィンドウは別の保存先を使う。`getAll` の `storeId` を省くと、実行中のコンテキストの保存先を使う | https://developer.chrome.com/docs/extensions/reference/api/cookies | 2026-11-22 |
