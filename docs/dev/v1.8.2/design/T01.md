# T01 設計メモ: 表示用の文言の整理とポップアップのレイアウト（C）

## 目的

ディストリ版を検出したページでポップアップの技術名が消える崩れと、候補が 2 件以上のときに確信度が二重に出る不具合を直す。判定側（`distro-inference.ts`）は表示用の文言を組み立てず、確信度は表示側でちょうど 1 回付ける（H4・H5、指示書 §3）。

## 仕様の解釈

受け入れ条件（指示書 §6 T01）を、テストで確かめられる形に言い直す。

1. **「確信度がちょうど 1 回」の数え方**
   - 数えるのは **OS の推定の確信度**（`確信度` の後に空白・`:`・`：` を挟んで `高`・`中`・`低` が続く表記。正規表現 `/確信度[\s:：]*[高中低]/g`）。検出の確信度（「確信度 70」「確信度スコア」「high (90%)」など数値・英語の表記）は数えない。
   - **`eolInfo.note`（と `distroInference.note`）の文字列は数えない。** §3.2-1 が「`eolInfo.note` は説明の全文なので確信度入りのまま」と決めているため。テストは出力から note の文字列を取り除いてから数える。
   - 出力先ごとの数え方（§3.3 の表）:

     | 出力先 | 関数 | 数える範囲 | 期待 |
     | --- | --- | --- | --- |
     | ポップアップの一覧 | `renderTechRowHtml(tech)`（新設） | 行全体 | **0 回**（「既存の確信度バッジだけ」。既存の検出の確信度バッジ `中 · 70` は残る） |
     | ポップアップのモーダル | `renderTechModalHtml(tech)` | 全体（note を除く） | 1 回 |
     | ダッシュボードの技術一覧 | `renderFullTechnologiesHtml([tech])` | 全体（note を除く） | 1 回 |
     | ダッシュボードのライブラリのセキュリティ表 | `renderLibrarySecurityTableHtml([tech])` | 全体（note を除く） | 1 回以下（§3.3 の表に無い場所。二重にならないことだけ見る） |
     | CSV | `exportReportToCsv` | 列「OSの推定」 | 1 回（「（推定・確信度 X）」）。列「サポート状態 (EOL)」には「確信度」が無い |
     | Markdown | `generateMarkdownReport` | 「OS リリースの推定」の表 | リリースの列（見出しに「推定リリース」を含む列）は名前だけ、確信度の列（見出し「確信度」）は `formatDistroConfidenceJp` の値。§6 の表の「サポート状況 (EOL)」の列に「確信度」が無い |
     | 指摘文 | `executeInspection` | `SEC-EOL-<技術>`（OS のライフサイクル由来）の `observed` と `description`、`SEC-DISTRO-CVE-<技術>` の `observed` | それぞれ 1 回 |

   - 候補 1 件（`release` あり・medium）と候補 2 件以上（`release: null`・low）を**別々に**確かめる（K1 設計の規則）。EOL のとき（標準サポート終了日を過去にした固定 DB）と、EOL でないときの両方を見る。
   - 目視の「CSV で確信度が 1 回だけ」は、列「OSの推定」で 1 回、と解釈する。列「推奨対応」には `eolInfo.note`（確信度入りの説明の全文）が入ることがあり、これは §3.2-1 で許されている。

2. **`eolInfo.label` に「確信度」が含まれない**: `judgeDistroEol` の戻り値の `eolInfo.label` は候補のリリース名だけ（「Ubuntu 20.04 LTS」「Ubuntu 20.04 LTS / Ubuntu 22.04 LTS」）。「確信度」「推定・」を含まない。`eolInfo.note` は確信度入りのまま（陽性で確かめる）。

3. **`formatDistroReleaseDisplay` の分岐 (2) の削除**: 候補 2 件以上で OS のライフサイクルの `eolInfo.label` があっても使わず、分岐 (3)（候補の名前を ` / ` で連結）と同じ結果にする。v1.8.1 以前に保存したレポート（label が確信度入り）を読んでも、リリース欄に確信度が出ない。

4. **`formatDistroReleaseWithConfidence(tech)`**: 推定があるときは「<リリース名>（推定・確信度 X）」。リリース名の部分は候補の名前をすべて含む。確信度はちょうど 1 回（v1.8.1 以前の確信度入りの label が付いていても）。第三者・バックポート・none（対応表に無い版）は従来どおり「推定なし」で、確信度を付けない（「推定なし（推定・確信度 なし）」のような断定めいた形にしない）。`distroInference` が無ければ `''`。

5. **第三者・none・対応表に無い版は従来どおり**: リリース欄は「推定なし」。モーダル・ダッシュボード・ポップアップの一覧・CSV の「OSの推定」に OS の推定の確信度（高・中・低）が出ない。OS のライフサイクルの EOL の指摘を出さない。CSV の「OSの推定」に「該当なし」「安全」「Not Affected」が出ない。

6. **ポップアップの一覧の「ディストリ版」（H5・§3.2-5）**: `distroHint` があると、`.item-meta`（バージョンとカテゴリの行）に、文字がちょうど「ディストリ版」の要素を置き、全文（「バックポートの可能性」を含む文）は `title` 属性に入れる。`.item-side` には「ディストリ版」を出さない。画面の文字に「ディストリ版（バックポートの可能性）」は出ない。`distroHint` が無ければ出さない（陰性）。`title` の値はエスケープする。

7. **CSS（§3.2-4）**: `.item-main { flex: 1 1 auto; min-width: 0; }`、`.item-side { flex-shrink: 1; flex-wrap: wrap; justify-content: flex-end; }`。ポップアップの `body` の幅は 450px のまま。Vitest では描画できないので CSS の宣言を読んで確かめ、実際の描画は E2E（下の「実装の方針」の E2E の節）で確かめる。

8. **候補が 2 件以上になる確認ページ**: v1.8.1 の T07 のページには候補が 2 件以上になるものが無いので、`/distro-multi-candidate` を足す。版は対応表から取る（ページに直接書かない）。

**曖昧だった点と判断**

- 「ディストリ版」の `title` の「全文」が何かは書かれていない。現状の短い文言「ディストリ版（バックポートの可能性）」と `distroHint`（「Ubuntu」など）を合わせたもの（例: 「ディストリ版（バックポートの可能性）: Ubuntu」）とする。テストは「バックポートの可能性」を含むことだけを見る。
- ポップアップの一覧の行を Vitest で確かめるため、行の HTML を作る処理を `src/popup/render.ts` の `renderTechRowHtml` に切り出す（popup.ts は DOM を前提に読み込み時に動くので、テストから読めない）。挙動は変えない。指示に無いリファクタリングではなく、受け入れ条件（ポップアップでの確信度の回数・「ディストリ版」の位置）を確かめるための最小の切り出しと判断した。
- ダッシュボードのバッジ（`render.ts:303, 547, 565`）の「ディストリ版（バックポートの可能性）」は §3.3 で「全文」のままなので変えない。
- v1.8.1 以前に保存したレポートの `eolInfo.label`（確信度入り）を、ダッシュボードの EOL バッジがそのまま出すのは直さない（保存データを書き換えない。指示に無い）。リリース欄（`formatDistroReleaseDisplay`）と指摘文の関数（`formatDistroReleaseWithConfidence`）は label の確信度を使わないので、そこでは二重にならない。

## 実装の方針

変更してよい場所: `src/`、`test-server/`、`scripts/test-e2e-smoke.mjs`、`docs/`（設計メモを除く）。`tests/` と設計メモは変更しない。

1. **`src/detection/distro-inference.ts`（`judgeDistroEol`、449 行付近）**
   - `const label = candidateNames.join(' / ');`（確信度と「推定・」を付けない）。
   - `note` は今のまま（`${basisName}（推定・確信度 ${confJp}）：…`）。`formatDistroConfidenceJp` の import は note で使うので残る。

2. **`src/shared/distro-display.ts`**
   - `formatDistroReleaseDisplay` の分岐 (2)（89〜91 行の `if (tech.eolInfo?.source === OS_LIFECYCLE_SOURCE && tech.eolInfo.label) return tech.eolInfo.label;`）を削除する。関数の先頭のコメント (1)〜(4) も直す。
   - 新設（export）:
     ```ts
     /**
      * リリース名に確信度を 1 回だけ付ける（指摘文用。例: 'Ubuntu 18.04 LTS（推定・確信度 高）'）
      * 推定が無い（第三者・バックポート・候補なし・none）は formatDistroReleaseDisplay と同じ（'推定なし'）。distroInference が無ければ ''
      */
     export function formatDistroReleaseWithConfidence(
       tech: Pick<DetectedTechnology, 'distroInference' | 'eolInfo'>
     ): string
     ```
     推奨の中身:
     - `inf = tech.distroInference` が無ければ `''`。
     - `display = formatDistroReleaseDisplay(tech)`。`inf.thirdParty`、候補が 0 件、`inf.confidence === 'none'` のいずれかなら `display` をそのまま返す（「推定なし」）。
     - 名前の部分: `tech.eolInfo?.source === OS_LIFECYCLE_SOURCE` で `tech.eolInfo.label` があり、label に「確信度」を含まなければ label（「LTS」付きの名前。今の指摘文の情報量を保つ）。それ以外は `display`。
     - 戻り値: `` `${name}（推定・確信度 ${formatDistroConfidenceJp(inf.confidence)}）` ``。
   - テストが前提にしている公開 API: `formatDistroReleaseDisplay`・`formatDistroReleaseName`・`formatDistroConfidenceJp`（既存）と `formatDistroReleaseWithConfidence`（新設）。

3. **`src/background/service-worker.ts`**

   - 927 行・930 行（`isDistroEol` の `eolObserved`・`eolDescription`）: `instEolInfo?.label || 'OS'` を `formatDistroReleaseWithConfidence(tech) || instEolInfo?.label || 'OS'` にする。観測値と説明のそれぞれに確信度が 1 回、候補の名前がすべて入る。
   - 1056 行（`SEC-DISTRO-CVE-*`）: `const releaseName = formatDistroReleaseWithConfidence(tech);`。観測値に確信度が 1 回入る。

4. **`src/popup/render.ts`** に新設（export）:

     - `document.body.getBoundingClientRect().width` が 450（±1）。
     - すべての `#techsList .item-row .item-main` の `getBoundingClientRect().width > 0`、その中の `.item-name` の幅も `> 0`。
     - `#techsList` と各 `.item-row` で `scrollWidth <= clientWidth + 1`（横スクロールが出ない）。
     - `/distro-ubuntu-apache-php` と `/distro-multi-candidate` で、`.item-meta` に「ディストリ版」がある行が 1 つ以上ある。
     - どれかが満たされなければ `throw new Error('… 450px …')`。スクリーンショットを `.tmp/popup-450-<ページ名>.png` に保存する。
   - 製品のコードに E2E 用の分岐を足さない（ページ側の `chrome.runtime.sendMessage` を E2E の中だけで包む）。E2E は人が実行する。

型（`EolInfo`・`DistroInference`・`DetectedTechnology`）は変えない。戻り値の形も変えない（`eolInfo.label` の中身の文字列だけが変わる）。

## 実装の担当への注意

- `formatDistroReleaseDisplay` を呼ぶ 4 つの出力（popup/render.ts・dashboard/render.ts・markdown.ts・csv.ts）は、その呼び出しを残す（`tests/distro-release-display-callers.test.ts`）。表示名を作る書き方（`'Red Hat Enterprise Linux '` など）は `src/shared/distro-display.ts` の外に書かない（`tests/distro-release-display.test.ts` の静的な確認）。test-server の OS 名の表は `test-server/` にあるので、この確認の対象（`src/`）の外。
- `eolInfo.note` から確信度を外さない（§3.2-1。`tests/distro-inference.test.ts` が note の「確信度 X」を見ている）。
- `eolInfo.label` が変わるのは OS のライフサイクルで判定したもの（`source: 'endoflife.date（OS のライフサイクル）'`）だけ。上流の EOL の label（「Limited Support (Maintenance)」など）は変えない。
- 推定にもとづく結果を断定しない（H4）。「推定なし」に確信度を付けない。「該当なし」「安全」を足さない。
- `renderTechRowHtml` で値を innerHTML に入れるときは、今の popup.ts と同じく `escapeHtml()` を通す。`title` 属性も同じ。インラインイベントハンドラは使わない（クリックは popup.ts の `addEventListener` のまま）。
- 新しいセキュリティチェックやチェック ID は足さない。`HEADER_DEPENDENT_CHECK_PREFIXES` は変えない。ルール JSON も変えないので `spec:generate` の差分は出ない見込み。
- テストの日付は「今日」からの相対で作っているので、固定 DB（`tests/fixtures/advisory-db.fixture.json`）を変えない（`tests/` は変更禁止）。
- `docs/DETECTION_SPECIFICATION.md` などに label の形（「（推定・確信度 X）」付き）を書いている箇所があれば、実態に合わせて直してよい（任意）。
