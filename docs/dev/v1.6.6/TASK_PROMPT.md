## この実行でやること

1. `AGENTS.md` と `docs/dev/v1.6.6/INSTRUCTIONS.md` の §1・§5・タスク {{TASK}} の節を読む。関係するソースとテストを読む。
2. **タスク {{TASK}} だけ**を実装する。ほかのタスクには手を付けない。指示にない変更はしない。
   - T12 の場合は、E2E の追加（INSTRUCTIONS.md の T12 の手順のうち、テストサーバーのルートとスモークテストの追加）までを行う。総合チェックと完了報告書は、別の実行で行う。
3. 指示されたテストを追加し、指定された受け入れテストの `it.skip` を外す（期待値は変えない）。
4. `docs/dev/v1.6.6/WORKLOG.md` に、指定の形式（`## {{TASK}} <タスク名>  (日時)`）で記録を追記する。同じタスクの節が既にあれば、その節を更新する。
5. 最後に、ファイル `.agy-out/result.json` を次の形で作る（ファイル編集ツールで作成する）。
   ```json
   {"task": "{{TASK}}", "status": "done", "summary": "<変更の要約。日本語で40文字以内>", "ids": "<指摘ID。例: SPEC-04, IMPL-04>", "note": "<人間に伝えたいこと。なければ空文字>"}
   ```
   - `status` は、完了なら `done`、一部だけなら `partial`、実装できなかったなら `incomplete`。
   - `partial` / `incomplete` のときは、理由と人間に判断してほしいことを WORKLOG と `note` に書く。

## この実行でやらないこと（スクリプトが代わりに行う）

- **`git add` / `git commit` をしない**（サンドボックスの中では `.git` に書き込めない）。この実行が終わると、スクリプトがサンドボックスの外で `npm run spec:generate` と `npm test` を実行し、通ればコミットする。
- **`npm test` / `npm run build` / `vitest` を実行しない**（サンドボックスの中では動かない）。テストが失敗した場合は、次の実行で結果を渡すので、そこで直す。型の確認に `npx tsc --noEmit` を試すのはよい（動かなくても気にしない）。
- ルール JSON を変更しても、`npm run spec:generate` は実行しなくてよい。
- リポジトリの外のファイルの読み書き、Web へのアクセスをしない（無人モードでは確認できず、実行全体が中断する）。
- 拒否された操作を再試行したり、別の書き方で回避したりしない。
