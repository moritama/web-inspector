# T04 設計メモ: 根拠の注記・Secure の内訳・確認ページ（A）

## 目的

T03 で確信度を下げた「親ドメイン（host-only でない）の Cookie 名だけで検出した技術」に、利用を断定しない注記を Markdown の §4・§14 とダッシュボードの根拠に出す（指示書 §4.2、H2）。Cookie の Secure 未設定の指摘に「うち N 件は親ドメインのスコープ」を添え、そのホストの管理者が直せない Cookie を区別する。あわせて、テストサーバーにサブドメインをまたぐ確認ページを足す。

## 仕様の解釈

受け入れ条件（指示書 §6 T04）と §4.2 を、テストで確かめられる形に言い直す。

### 1. 根拠の注記

1. **注記を出す条件**: 技術に `cookieScopeDowngraded === true`（T03 の印。根拠がすべて `cookie-name` で、どれも host でなく、従来なら一覧に出ていた）が付いているとき**だけ**。
   - 受け入れ「親ドメインの Cookie だけのとき注記が出る」→ 印あり。
   - 受け入れ「host-only だけのとき出ない」→ 印なし。同じ名前に host と domain が混在（H3 で host）、親ドメインの Cookie ＋ script-url（H2 で下げない）も印が無いので出さない。後者は script で利用を確かめているので「利用は確認できていない」と書くと誤りになる。
   - 印の無い保存済みレポート（v1.8.1 以前）には出さない（`cookieScope` が無く判断できないため。断定しない側）。
   - 印があっても、根拠に `cookie-name` 以外（連動検出の `pattern` など）が 1 つでもあれば出さない。T03 の WORKLOG の未解決のとおり、連動検出（`engine.ts` の Implication）は下げた技術に後から根拠を足して確信度を上げるが、印は消さない。その場合は他の技術から利用が示されているので、「利用は確認できていません」と書くと誤りになる（H2「他の根拠が 1 つでもあれば下げない」と揃える）。
2. **注記の中身**（§4.2 の趣旨、§7 の既存の注記と揃える）: 次を含む 1 文〜2 文。
   - 根拠の Cookie 名（`cookie-name` の根拠のうち `cookieScope !== 'host'` のもの。重複は 1 回）。根拠でない Cookie の名前は入れない。
   - スコープのドメイン: レポートの `cookies` のうち、同じ名前で `hostOnly === false` の Cookie の `domain`（重複を除き、出現順）。複数あればすべて。見つからない（`cookies` を渡されない、`document.cookie` だけ＝スコープ不明）ときはドメインを書かない。
   - 「別サイト」と「このホスト単体での利用は確認できていません」の語句を、注記 1 つにつき**ちょうど 1 回**（Cookie 名が複数でも 1 回。v1.8.1 の確信度の二重表示の教訓）。
   - 推奨の文言（実装はこれに合わせる。テストは上の語句・名前・ドメインだけを見る）:
     - `根拠の Cookie _ga（.example.test）は、このホスト専用（host-only）の Cookie ではありません。同一ドメインの別サイトで発行された可能性があり、このホスト単体での利用は確認できていません。`
     - 名前ごとの括弧: ドメインが分かる → `（.example.test・.app.example.test）`、`domain` だがドメイン不明 → `（親ドメイン）`、`unknown` → `（スコープ不明）`。名前の区切りは `、`。
3. **出す場所**:
   - Markdown §4（検出技術スタック）: 表の後に、下げた技術ごとに「技術名: 注記」の行（`> [!NOTE]` のブロックでよい）。下げた技術が無ければ何も足さない。
   - Markdown §14（検出根拠）: 該当する技術の `### 技術名 (確信度: …)` の節の中、根拠の行の後に 1 行（例 `- ※ 注記`）。他の技術の節には出さない。
   - ダッシュボード（`renderFullTechnologiesHtml`）: その技術の「判定根拠 (Evidence)」の見出しより後（根拠の一覧の直後でよい）。
   - ポップアップ・CSV には出さない（§4.2 が挙げていない。ポップアップの文字列を増やさないので 450px の見え方は変わらない。H12）。
4. **§7 の既存の注記**（`isParentDomainCookie`、v1.7.1）は変えない。

### 2. Secure 未設定の内訳

5. 対象の指摘: `SEC-COOKIE-SECURE`（認証）、`SEC-COOKIE-SECURE-CSRF`、`SEC-COOKIE-SECURE-GENERAL`。HttpOnly などそれ以外の指摘には付けない。HTTP のページ（`isHttps === false`）はもともと Secure の指摘が出ないので内訳も無い。
6. **N の数え方**: その指摘の Secure 未設定の Cookie（`observed` の先頭の「N 件」と同じ単位。同じ名前が 2 つのドメインにあれば 2 件）のうち、入力の Cookie の `hostOnly === false` のもの。H1 のとおり、ドメインの文字列（先頭の `.`）やホスト名との比較では数えない。`hostOnly` が真偽値でない互換データは数えない（T03 と同じ。断定しない側）。したがって N ≤ 総数。
7. **持ち方**: `SecurityCheckResult` に任意の `parentDomainCookieCount?: number` を足し、N ≥ 1 のときだけキーを付ける（0 のときはキーなし）。**`observed` の文字列は変えない**（ポップアップのセキュリティ一覧 `popup/render.ts` と差分 `diff.ts` が `observed` を使うため、450px の表示と前回との差分に影響させない）。
8. **表示**（§4.2「Markdown・ダッシュボード」）: Markdown §5 の観測値の列と、ダッシュボードの「観測値」に `（うち N 件は親ドメインのスコープ）` を添える。キーが無い（0・旧レポート）ときは何も添えない。「うち 0 件」とは書かない。

### 3. 確認ページ

9. `test-server/server.mjs` に 2 ページを足す。
   - `/parent-cookie-issuer`: リクエストの Host のホスト名（ポートを除く、小文字）が `*.localtest.me` なら `Domain=localtest.me`、`*.example.test` なら `Domain=example.test` の `_ga` を発行する。それ以外（`localhost` など）では Domain 付きの `_ga` を発行せず、開くべき URL を案内する。GA のスクリプトは読み込まない。
   - `/parent-cookie-target`: `_ga` を発行せず、GA のスクリプトも読み込まない。issuer への案内を書く。
   - どちらのページにも、名前解決できない環境（ルーターの DNS リバインディング対策など）の代わりの手順として、`/etc/hosts` に `127.0.0.1 issuer.example.test` と `127.0.0.1 app.example.test` を足し、`http://issuer.example.test:3000/parent-cookie-issuer` → `http://app.example.test:3000/parent-cookie-target` の順に開く手順を書く。
   - `/clear-cookies` は、Host が上の 2 つのどちらかなら、親ドメインの `_ga` も期限切れにする（既存の host-only の消去は残す）。
10. 既存の Cookie 判定（T03）だけで、target のページを調べると GA が low になる（issuer の Set-Cookie を検出エンジンに渡すテストで確かめる）。

**曖昧だった点と判断**

- **§4 の注記の置き場所**: 指示書は「§4・§14・ダッシュボードの根拠に」とだけ書く。§4 は表なので、セルに長文を入れず表の後に置いた（表の列を増やすと既存の列数の検査に響くため）。
- **注記の条件を `cookieScopeDowngraded` にした理由**: 根拠から毎回計算し直す方法もあるが、T03 で「従来 50 未満だったものは一覧に出さない」と決めており、一覧に出ている下げた技術とちょうど一致するのは印のほう。
- **Secure の内訳を `observed` に埋め込まない**: §4.2 は「観測値に添える（Markdown・ダッシュボード）」とし、ポップアップを挙げていない。`observed` を変えるとポップアップの行が長くなり（H12）、前回のレポートとの差分（`diff.ts` の before / after）に変化が出る。別の項目に持ち、表示の側で添える。
- **確認ページのホスト名**: 指示書の例 `*.localtest.me` を使う。`localtest.me` は公開の DNS で自分自身とすべてのサブドメインを 127.0.0.1 に向けるドメイン（外部の事実の表）。同梱の Public Suffix List（`data/psl/public_suffix_list.dat`）に `localtest.me` は無く（`me` だけ）、`Domain=localtest.me` の Cookie はブラウザに受け入れられる。代わりの手順のホスト名は、AGENTS.md の合成データの規則に合わせて `*.example.test`（RFC 6761 の予約名。PSL に `test` は無い）。
- **Secure の内訳の目視**: テストサーバーは HTTP だけで、Secure の指摘は HTTPS でしか出ない（H7 で Cookie の Secure は HTTPS かどうかで見るまま）。目視は無し（Vitest で確かめる）。

## 実装の方針

変更してよい場所: `src/shared/types.ts`、`src/shared/cookie-scope-note.ts`（新規）、`src/security/cookies.ts`、`src/export/markdown.ts`、`src/dashboard/render.ts`、`src/dashboard/dashboard.ts`、`test-server/server.mjs`、`docs/`（設計メモを除く。任意）。`tests/` と設計メモは変更しない。ルール JSON・検出エンジン（`src/detection/engine.ts`）・manifest・ポップアップは変えない。

### 1. `src/shared/types.ts`

`SecurityCheckResult` に任意の項目を足す。

```ts
  /** Secure 未設定の Cookie のうち、親ドメインのスコープ（hostOnly === false）の件数。1 以上のときだけ付ける (v1.8.2 T04) */
  parentDomainCookieCount?: number;
```

### 2. `src/shared/cookie-scope-note.ts`（新規）

```ts
import type { DetectedTechnology, InspectedCookieInfo } from './types';

/**
 * 親ドメイン（host-only でない）の Cookie 名だけで検出した技術の注記を返す (v1.8.2 T04 / §4.2)
 * tech.cookieScopeDowngraded !== true なら null
 */
export function formatCookieScopeNote(
  tech: DetectedTechnology,
  cookies?: readonly InspectedCookieInfo[]
): string | null;
```

- 条件: `tech.cookieScopeDowngraded === true`、かつ `tech.evidence` のすべてが `type === 'cookie-name'` で `cookieScope !== 'host'`。どちらかを満たさなければ null。
- 名前: `tech.evidence` のうち `type === 'cookie-name'` かつ `cookieScope !== 'host'` の `name`（重複を除く、出現順）。名前が 1 つも無ければ null。
- ドメイン: `cookies` のうち `c.name === 名前 && c.hostOnly === false && c.domain` の `domain`（重複を除く）。
- 文言は「仕様の解釈」2 の推奨の形。プレーンな文字列で返す（HTML・Markdown のエスケープは呼び出し側）。
- `instances` は見ない（Cookie 名の技術は版のインスタンスを持たない）。

### 3. `src/security/cookies.ts`（`checkCookies`）

- ループで、各 `issue` に対応する入力の Cookie の `hostOnly === false` を覚える（例: `issue` と並べた配列、または `Map<CookieIssue, boolean>`）。`evaluateCookie` の戻り値の形（`CookieIssue`）は変えない（既存テストが `missingAttributes` などを見ている）。
- 3 つの Secure の指摘を作るところで、`missingSecure` のうち親ドメインのものを数え、1 以上なら `parentDomainCookieCount: n` を付ける（`...(n > 0 ? { parentDomainCookieCount: n } : {})`）。
- `observed`・`description`・`checkId`・`status`・`severity` は変えない。

### 4. `src/export/markdown.ts`

- §4: 表（と既存の distro の節）の後に、`report.technologies` のうち `formatCookieScopeNote(t, report.cookies)` が null でないものを並べる。例:
  ```
  > [!NOTE]
  > **親ドメインの Cookie だけで検出した技術:**
  > - **Google Analytics**: 根拠の Cookie _ga（.example.test）は、…確認できていません。
  ```
  注記は `escapeMarkdownTableCell` か `escapeMarkdown` でエスケープしてよい（テストは `\` と `` ` `` を除いて比べる）。
- §14: `formatTechEvidenceSection` の中で、根拠の行・プラグイン・テーマの行の後に `- ※ ${注記}` を足す（注記があるときだけ）。`formatTechEvidenceSection` は `report.cookies` を参照できるよう、クロージャのまま使ってよい。
- §5: 観測値の列を `formatMarkdownCodeSpan(c.observed, { inTable: true })` のあとに、`typeof c.parentDomainCookieCount === 'number' && c.parentDomainCookieCount > 0` なら ` （うち ${n} 件は親ドメインのスコープ）` を添える（コードスパンの外）。
- §7 の既存の注記（`isParentDomainCookie`）は変えない。

### 5. `src/dashboard/render.ts` と `dashboard.ts`

- `renderFullTechnologiesHtml(techs, coverage?, cookies?: readonly InspectedCookieInfo[])` と第 3 引数を任意で足す。既存の 2 引数の呼び出しは変えずに動くこと（その場合も注記は出る。ドメインが書かれないだけ）。
- 「判定根拠 (Evidence)」の `<ul>` の後に、注記があれば `<div …>※ ${escapeHtml(note)}</div>` を出す。値は必ず `escapeHtml()` を通す。
- `renderFullSecurityHtml` の観測値: `<code>${escapeHtml(c.observed)}</code>` の後に、件数があれば ` （うち ${n} 件は親ドメインのスコープ）` を添える（n は数値であることを確かめる）。
- `dashboard.ts` の `renderFullTechnologies(report.technologies, report.coverage)` を、`report.cookies` も渡すように変える（関数の引数を 1 つ足す）。

### 6. `test-server/server.mjs`

- `createRequestHandler` の中に `/parent-cookie-issuer` と `/parent-cookie-target` を足す（Host は `req.headers.host` から取る。既存の `host` 変数を使ってよい）。親ドメインの決め方は「仕様の解釈」9（`.localtest.me` で終わる → `localtest.me`、`.example.test` で終わる → `example.test`、それ以外は無し）。
  - issuer の Set-Cookie の例: `_ga=GA1.1.1000000000.1700000000; Domain=localtest.me; Path=/; SameSite=Lax`（Secure は付けない。HTTP のため）。
  - 本文: 見出しに自分のパス、issuer → target の順に開く手順（`http://issuer.localtest.me:3000/parent-cookie-issuer` → `http://app.localtest.me:3000/parent-cookie-target`）、`/etc/hosts` の代わりの手順（`127.0.0.1 issuer.example.test`、`127.0.0.1 app.example.test`）、期待する結果（GA が low、§14 に注記）。ポートは `PORT` を使う。
  - GA のスクリプト（`googletagmanager.com/gtag/js`・`google-analytics.com/analytics.js`）を本文に書かない（説明文にも URL を書かない）。
- `TEST_PAGES` に 2 ページを足す（ラベル例: 「親ドメインの Cookie の発行（サブドメインをまたぐ確認）」「親ドメインの Cookie の確認先（別のサブドメイン）」）。既存のテストが `http://localhost:${port}${path}` の行を見るので、その行はそのまま出る。
- `getStartupLines(port)` の最後に、`http://issuer.localtest.me:${port}/parent-cookie-issuer` と `http://app.localtest.me:${port}/parent-cookie-target` を含む行を足す（既存の行は変えない）。
- `/clear-cookies`: Host の親ドメインが決まるときは、`_ga=deleted; Domain=<親ドメイン>; Path=/; Expires=Thu, 01 Jan 1970 00:00:00 GMT; Max-Age=0` を足す。既存の行は残す。
- 冒頭のコメントの一覧（任意）とナビ（任意）は変えてよい。

## 実装の担当への注意

- **注記の条件は `cookieScopeDowngraded === true` かつ、根拠がすべて host でない `cookie-name`**。`cookie-name` の根拠に `cookieScope: 'domain'` があるだけで出すと、script-url でも確かめた高い確信度の技術に「利用は確認できていません」と書き、誤りになる。逆に印だけで出すと、連動検出で後から根拠が足された技術にも出てしまう（印は連動検出で消えない）。`engine.ts` の印の付け方は変えず、`formatCookieScopeNote` の側で根拠を確かめる。
- **趣旨の語句（「このホスト単体での利用は確認できていません」）は注記 1 つに 1 回**。Cookie 名ごとに繰り返さない。§14 でも 1 つの技術の節に 1 回。
- **`observed` を変えない**。内訳は `parentDomainCookieCount` に持ち、Markdown §5 とダッシュボードの表示で添える。ポップアップの行は変えない（H12）。
- **N は `hostOnly === false` で数える**。`domain` の先頭の `.` やホスト名との比較で数えない（H1）。`isParentDomainCookie`（§7 の注記、v1.7.1）は変えない・流用しない。
- 件数が 0 のときはキーを付けない。表示で「うち 0 件」と書かない。
- ダッシュボードに出す注記・Cookie 名・ドメインは必ず `escapeHtml()` を通す。
- 検出エンジン（`engine.ts`）・ルール JSON は変えない（T03 の判定はそのまま）。
- `HEADER_DEPENDENT_CHECK_PREFIXES` は関係しない（新しいセキュリティチェックは足さない。既存の Cookie の指摘に任意の項目を足すだけ）。
- テストサーバーのページに実サイトのホスト名を書かない（`localtest.me` は指示書が挙げたテスト用ドメイン、`*.example.test` は予約名）。GA のスクリプトの URL も書かない。
- E2E（`scripts/test-e2e-smoke.mjs`）への追加は不要（ポップアップの文字列を増やさない）。
