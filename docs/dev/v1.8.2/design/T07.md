# T07 設計メモ — 出典とライセンスの表示と文書（E）

## 目的

同梱データ（§5.2 の表の 7 種類）の出典・ライセンス・加工の有無を、`THIRD_PARTY_NOTICES.md`（zip にも入れる）、ダッシュボードの「データの出典とライセンス」欄、Markdown のレポートの末尾、README のライセンスの節に載せる。NVD の表示文はダッシュボードの欄に載せ、ポップアップはその欄へのリンクだけにする（H9・H11・H12、指示書 §5.4）。

## 仕様の解釈

| 受け入れ条件（§6 T07・§5.4） | テストで確かめる形 |
| --- | --- |
| DB の出典がすべて `THIRD_PARTY_NOTICES.md` にある（CI） | 同梱 DB の `sources` と `distro._source` の各出典の**名前と URL の両方**が NOTICES にある。`scripts/ci/check-data-sources.mjs` の `checkDataSources` が同梱 DB と NOTICES で合格し、「照合をスキップ」の警告を出さない（＝NOTICES がある）。陰性: NOTICES に無い出典を入れた DB は不合格 |
| NOTICES の中身（§5.4） | 7 種類それぞれに見出しの節があり、節の中に出典の URL・ライセンスの表記（とライセンスの URL）・「加工」の有無がある。MIT は著作権表示と許諾の本文、MPL 2.0 は本文への参照（URL）と元のファイルの URL。Ubuntu は CC BY-SA 4.0 と明記。陰性: Debian の節にライセンスを割り当てない。陰性: Launchpad・sources.debian.org を見出しにしない |
| NVD の表示文が拡張機能内にある（H11） | ダッシュボードの `#dataSourcesView` に、表示文が一字一句あり、利用規約へのリンクがある。調査結果が 1 件も無くても出る |
| ダッシュボードの欄に 7 種類 | 欄に 7 種類の名前・ライセンスの表記・出典の URL へのリンク（ライセンスの URL があればそれも） |
| ポップアップはその欄へのリンクだけ（H11） | `popup.html` の `#dataSourcesLink` をクリックすると `chrome.tabs.create({ url: <getURL の結果>#dataSourcesView })`。陰性: 既存の「ダッシュボードを開く」はハッシュ無しのまま。陰性: ポップアップのソースに表示文・出典の一覧を持たない |
| ポップアップのリンクから欄へ移れる | ダッシュボードは URL のハッシュが `#dataSourcesView` なら初期表示でその欄を開く。陰性: ハッシュ無し・存在しない id・ナビの無い要素の id・HTML やセレクタとして不正な値は、概要サマリーのままで例外を出さない |
| ポップアップ 450px で崩れない（H12） | Vitest: リンクの文言は「出典」を含み 20 文字以内、インラインイベントハンドラ無し。描画は E2E（下の「実装の方針」）で確かめる |
| Markdown の末尾に出典の節 | 最後の `## ` の見出しが「出典」を含む唯一の見出しで、§15 より後。節に NVD の表示文と 7 種類の名前・ライセンスの表記・URL。技術が 0 件のレポートでも出る |
| zip に NOTICES が入る | `scripts/package.mjs` をカレントディレクトリ（os.tmpdir の作業場所、realpath 済み）で実行すると、zip の直下に `THIRD_PARTY_NOTICES.md` が入る。陰性: NOTICES が無ければ終了コード 0 以外で、zip を作らない |
| README のライセンスの節 | `## ライセンス` の節に「MIT」「同梱データ」「Ubuntu」「CC BY-SA 4.0」「THIRD_PARTY_NOTICES.md」 |

解釈したこと:

- **7 種類** = §5.2 の表の行（NVD・GitHub Advisory Database・Ubuntu・Debian・endoflife.date・CISA KEV・Public Suffix List）。DB の `sources` に入るのは PSL 以外の 6 つ（T06）。PSL は `psl-rules.generated.ts` として同梱されるので、表示の一覧には入れる。Launchpad・sources.debian.org・curated.json は表示しない（§5.2 の表の下）。
- 表示の一覧の名前と URL は、DB の `sources` の名前と URL と同じにする（照合を名前・URL の文字列で行うため。T06 の `scripts/advisories/lib/sources.mjs` の値と同じ）。
- `check-data-sources.mjs` は T06 のもの（NOTICES が無いと警告で飛ばす）。T07 は `scripts/ci/` を変えられない（K2.2）ので、「NOTICES がある・照合を飛ばさない」は Vitest（同梱 DB を読んでよい `tests/advisory-db-invariants.test.ts`）で確かめる。
- 「加工の有無」は各出典の `modification` の文で書く。NVD は利用規約に従い「加工した内容は NVD の提供ではない」趣旨を入れる。
- ハッシュで開ける欄は、`.nav-item[data-view="<id>"]` があるものだけ（ナビの無い id・不正な値は無視）。既存のナビのクリックの処理を流用し、初期表示で該当のナビをクリックしたのと同じにする。
- NVD の表示文は、指示書 §5.2 と NVD の Terms of Use の文（「This product uses the NVD API but is not endorsed or certified by the NVD.」）を使う。NVD の Start Here のページには「uses data from the NVD API」という別の言い回しがあるが、指示書が資料に挙げる Terms of Use のほうに合わせる（「外部の事実」）。
- endoflife.date の製品説明（Wikipedia 由来）を使っていないこと: build-db は `/api/<slug>.json` のサイクル（cycle・releaseDate・eol・support など）だけを `compactEolCycles`・`normalizeEol`（`scripts/advisories/lib/eol.mjs`）で使い、DB の `eol` は cycle・eolDate・status（label・note は catalog.json の自作の上書き）だけ。説明文は入っていない（コードで確認）。

## 実装の方針

### 1. `src/shared/data-sources.ts`（新規）

テストが前提にする公開 API（名前・型を変えない）:

```ts
export type BundledDataSourceId = 'nvd' | 'ghsa' | 'ubuntu' | 'debian' | 'endoflife' | 'kev' | 'psl';

export interface BundledDataSource {
  id: BundledDataSourceId;
  /** 出典の名前（DB の sources の name と同じ） */
  name: string;
  /** 出典の URL（https。DB の sources の url と同じ） */
  url: string;
  /** SPDX の ID。ライセンスが無い・明記なしは null */
  license: string | null;
  /** 画面と文書に出すライセンスの表記 */
  licenseLabel: string;
  /** ライセンス（NVD は利用規約）の URL。無ければ null */
  licenseUrl: string | null;
  /** 同梱しているもの */
  contents: string;
  /** 加工の有無 */
  modification: string;
}

export const NVD_NOTICE: string;          // 'This product uses the NVD API but is not endorsed or certified by the NVD.'
```

### 2. `THIRD_PARTY_NOTICES.md`（リポジトリ直下、新規）

- 冒頭に、コードは MIT（`LICENSE`）で、同梱データはそれぞれのライセンスに従う旨。
- 出典ごとに見出しの節（`## ` か `### `）を 7 つ。**見出しの行に `name` をそのまま入れる**（例 `### OSV.dev (Debian Security Tracker)`）。節の中に `url`、`licenseLabel`、`licenseUrl`（null でなければ）、同梱しているもの、加工の有無（「加工」の語を含む）。
- NVD の節: `NVD_NOTICE` の英文を一字一句と、`NVD_TERMS_URL`。
- Ubuntu の節: 「CC BY-SA 4.0」と `https://creativecommons.org/licenses/by-sa/4.0/`。
- Debian の節: 「ライセンスの明記なし」とだけ書く。**Debian の節（次の同じか上の階層の見出しまで）に `creativecommons.org`・`CC BY`・`CC0`・`MIT License`・`Mozilla Public License`・`GPL` を書かない**（テストが陰性で見る。OSV.dev の他のデータのライセンスにも触れない）。
- endoflife.date: 「外部の事実」の MIT の全文（著作権表示 `Copyright 2020 endoflife.date contributors` を含む）をそのまま載せる。
- Public Suffix List の節: `https://mozilla.org/MPL/2.0/`（本文への参照）、元のファイル `https://publicsuffix.org/list/public_suffix_list.dat`、生成ファイル `src/security/psl-rules.generated.ts` の名前。
- Launchpad・sources.debian.org・curated.json を出典の見出しにしない（「表示不要のもの」として本文で触れるのは可だが、見出しにしない）。
- ローカルパス・ユーザー名を書かない。

### 3. ダッシュボード（`dashboard.html`・`src/dashboard/dashboard.ts`・`src/dashboard/render.ts`）

- `dashboard.html` のサイドバーの `nav.sidebar-nav` の末尾に `<button class="nav-item" data-view="dataSourcesView"><span class="nav-icon">📚</span> データの出典</button>`（文言は「出典」を含む）。
- `<main>` の末尾に `<section id="dataSourcesView" class="view-panel">`。中に見出し「データの出典とライセンス」（**HTML に直接書く**。テストは init の前に textContent を見る）と、中身を入れる入れ物（例 `<div id="dataSourcesContainer"></div>`）。
- `render.ts` に `export function renderDataSourcesHtml(): string` を足し、`BUNDLED_DATA_SOURCES` と `NVD_NOTICE` から作る。NVD の表示文は目立つ枠で先頭に置き、`NVD_TERMS_URL` へのリンクを付ける。各出典は名前・`licenseLabel`・同梱しているもの・加工の有無と、`url`・`licenseUrl` へのリンク。値は `escapeHtml()`、href は `safeHref()`（https のみ）を通し、`target="_blank" rel="noopener noreferrer"`。インラインイベントハンドラを使わない。
- `dashboard.ts` の `initDashboard` で、`setupNav()` の後に欄の中身を描画し（調査結果に依存しない。`loadDashboardData` の前でよい）、URL のハッシュの欄を開く処理を足す:
  - `location.hash` から `#` を外し、`/^[A-Za-z][A-Za-z0-9_-]*$/` に合わなければ何もしない（`decodeURIComponent` で例外が出ても握りつぶす）
  - `document.querySelector(`.nav-item[data-view="${id}"]`)` があれば、その要素に `click` を送る（既存のナビの処理で切り替える）。無ければ何もしない
  - `initDashboard` は何度呼ばれても壊れない（テストは import 時の自動起動の後にもう一度呼ぶ）
- 既存の `viewReport` が概要へ戻す処理などは変えない。

### 4. ポップアップ（`popup.html`・`src/popup/popup.ts`・`src/popup/popup.css`）

- `popup.html` の `<footer class="footer">` の中（例: 左のボタンの組の後）に `<button id="dataSourcesLink" class="footer-link" title="データの出典とライセンス（ダッシュボード）">出典・ライセンス</button>`。文言は「出典」を含み 20 文字以内。
- `popup.ts`: `dataSourcesLink` のクリックで `chrome.tabs.create({ url: chrome.runtime.getURL('dashboard.html') + '#' + DATA_SOURCES_VIEW_ID })`（`DATA_SOURCES_VIEW_ID` は `src/shared/data-sources.ts` から import してよい。**`BUNDLED_DATA_SOURCES` と NVD の表示文はポップアップの側（popup.html・popup.ts・popup/render.ts）に持たない**）。既存の `openDashboard` はハッシュ無しのまま。
- CSS: 小さい文字（11px 前後）、折り返さない（`white-space: nowrap`）、450px で `.footer` からはみ出さない。必要なら `.footer` に `flex-wrap: wrap; gap` を足す。
- E2E（`scripts/test-e2e-smoke.mjs`、実装の工程で足す。実行は人）: 検証 9「ポップアップ 450px の出典リンク（T07）」
  1. `http://localhost:3000/distro-ubuntu-apache-php` を調べた状態のポップアップ（検証 8 と同じ開き方）で、`#dataSourcesLink` の幅が 0 より大きく、`getBoundingClientRect().right <= 450`、`.footer` と `document.documentElement` に横スクロールが無い（`scrollWidth <= clientWidth + 1`）
  2. `#dataSourcesLink` をクリックして開いたタブの URL が `dashboard.html#dataSourcesView` で終わり、そのページで `#dataSourcesView` が `.active`、textContent に NVD の表示文がある

### 5. Markdown（`src/export/markdown.ts`）

- §15 の後に `## 16. データの出典とライセンス` を足す（**「出典」を含む `## ` の見出しはこれだけ**）。中身は `NVD_NOTICE` と、`BUNDLED_DATA_SOURCES` の各出典の名前・`licenseLabel`・`url`（表か箇条書き。表なら `escapeMarkdownTableCell` を通す）、「詳細は THIRD_PARTY_NOTICES.md」。調査結果に依存しない。
- report-lint の `extractMarkdownSection(markdown, '## 1.')` は `## 16.` に一致しない（`'## 1.'` の前方一致）ので影響しない。
- **節の文面は次のとおりに固定する**（`tests/fixtures/reports/*.md` の 4 件に、設計の工程でこの文面を足してある。`tests/report-lint.test.ts` が JSON から作った Markdown と保存済みの .md を全体で比べるため、1 文字でも違うと落ちる）。§15 の最後の行の後は、今までの節と同じく空行 2 つ。

### 6. `scripts/package.mjs`

- zip を作る前に `path.join(process.cwd(), 'THIRD_PARTY_NOTICES.md')` があるかを確かめ、無ければ「THIRD_PARTY_NOTICES.md」を含むエラーを出して `process.exit(1)`（`release/` に zip を作らない）。
- dist の zip の後に、NOTICES を zip の直下に足す（例 `zip -j "<zipPath>" "<rootDir>/THIRD_PARTY_NOTICES.md"`）。失敗したら作りかけの zip を消して終了コード 1。
- 基準は今までどおり `process.cwd()`（テストは os.tmpdir の作業場所をカレントディレクトリにして実行する）。

### 7. `README.md`

`## ライセンス` の節を「コードは MIT License です。同梱データはそれぞれのライセンスに従います（Ubuntu の部分は CC BY-SA 4.0）。詳細は THIRD_PARTY_NOTICES.md を参照してください。」の趣旨にする。README では「THIRD_PARTY_NOTICES.md」を、リポジトリ直下の同じ名前のファイルへの相対リンクにする（この設計メモにはリンクを書かない。`npm run test:links` はファイルからの相対で見るため）。

## 実装の担当への注意

- `tests/` と設計メモは変えない。期待値が仕様と合わないと考えたら `needsTestChange: true` で止める。
- `scripts/ci/`・`.github/`・`data/`・`advisory-db.json` は T07 では変えない（K2.2・K2.3）。NOTICES を DB に合わせる（DB を NOTICES に合わせない）。
- NVD の表示文は英文のまま一字一句（訳さない）。`NVD_NOTICE` の定数を 1 か所に置き、ダッシュボード・Markdown はそこから取る。NOTICES は同じ文を手で書く。
- Debian の節・表記にライセンスを推測で足さない（H9）。
- innerHTML に入れる値は `escapeHtml()`、href は `safeHref()`。ハッシュの値をセレクタや innerHTML に入れる前に、必ず書式を検査する。
- 新しいセキュリティチェックは足さない（`HEADER_DEPENDENT_CHECK_PREFIXES` は関係しない）。拡張機能から外部へ通信しない（出典のリンクは利用者がクリックしたときに新しいタブで開くだけ）。
- ポップアップの文言を長くしない（450px、H12）。`.item-main` の幅など T01 のレイアウトを壊さない。
- `npm run spec:generate` で DETECTION_SPECIFICATION の生成物が変わる場合は夜のシェルが行う。
- NOTICES・README にローカルパス・ユーザー名・エージェントの製品名・作業キットへのリンクを書かない。
