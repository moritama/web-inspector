# T09 設計メモ — 版上げ 1.8.0 と文書

## 目的

版の表記を 1.8.0 にそろえ、README・仕様書・保守ガイド・PRIVACY_POLICY を v1.8.0 の変更（T01〜T08）に合わせる。テストは、版の表記が package.json の版と一致することと、文書に必要な記述があることを確かめる。

### G5 の `report-to` について（判断）

現在の `ALLOWED_RESPONSE_HEADERS` には `report-to` が無い（テストで確認: 8 つのうち `report-to` だけが無い）。T07 の設計メモは「`report-to` ヘッダーは T07 の判定には使わない（足すかどうかは任意）」としていたが、G5 は決定済みの事項で「取得するレスポンスヘッダーに … report-to … を追加する」とある。T09 は PRIVACY_POLICY を G5 に合わせるタスクなので、**G5 どおり `report-to` を許可リストに足す**ことをテストで求める。

- 足しても新しい指摘は出ない（どのチェックも `report-to` ヘッダーを読まない）。警告は増えない。
- `Report-To` ヘッダーの値はレポートの送信先の URL で、Cookie や認証情報ではない。保持する範囲は他のヘッダーと同じ（メインフレーム、セッションストレージ、タブを閉じるまで）。PRIVACY_POLICY に名前を書く。

## 実装の方針

1. **版（1.8.0）**: 次をすべて `1.8.0` にする。
   - `package.json` の `version`、`package-lock.json` の `version` と `packages[""].version`（自パッケージの版だけ。依存の記述は変えない。§2.2）
   - `public/manifest.json` の `version`（`1.7.1.1` → `1.8.0`。4 つ目は付けない）
   - `src/detection/rules/index.ts` の `RULES_VERSION`
   - 予備の文字列: `src/background/service-worker.ts`（`EXTENSION_VERSION`）、`src/popup/popup.ts`・`src/dashboard/dashboard.ts`（`setupVersionBadge` 付近）、`src/export/markdown.ts`（`extVer`）、`src/export/csv.ts`（2 か所）
   - `popup.html` の `id="brandVersion"`、`dashboard.html` の `id="dashboardVersion"` の中身を `v1.8.0`
   - `README.md` のバッジ（`version-1.8.0-blue.svg`）と、見出し `## 機能一覧 (v1.8.0)`（目次にリンクがあれば、そのアンカーも合わせる）
   - `docs/DETECTION_SPECIFICATION.md` の `**対象バージョン：** v1.8.0`
   - 日付の予備の値（`'2026-10-23'` など、DB の版の予備）は変えない。`advisory-db.json` の `minExtensionVersion` も変えない（DB は v1.8.0 では変えない）。
2. **`src/security/headers.ts`**: `SECURITY_HEADER_NAMES` に `'report-to'` を足す（G5。`ALLOWED_RESPONSE_HEADERS` はここから作られる。`SECURITY_HEADER_NAMES` は許可リストを作るためだけに使われている）。`checkHttpHeaders` に項目は足さない。
3. **`README.md`**: 機能一覧に v1.8.0 の変更（WAF・ボット確認画面の検出と警告、HSTS の 1 行化・プレリリース表記、NEW-03 の追加の指摘、一括取得の待ち方、CI の予行とサイズ上限）を短く足す（内容はテストで縛らない）。カバレッジ表は `npm run spec:generate` が作る（夜間はスクリプトが実行する）。
4. **`docs/MAINTENANCE_GUIDE.md`**: 次の節を足すか、既存の節に書き足す。
   - テストの書き方のルール: 版・件数・日付・dataVersion を直接書かない（版は `tests/helpers/release-version.ts` の `readPackageVersion()` で package.json から取る。manifest との比較は `isSameRelease`）。照合のテストは固定 DB `tests/fixtures/advisory-db.fixture.json` を使う。同梱 DB を読んでよいのは許可リストのテストだけ。`tests/test-hygiene.test.ts` がこれを検査する。
   - DB だけのリリースの予行: `node scripts/ci/rehearse-db-release.mjs`（何をするか、CI のどのジョブで動くか）。
   - サイズ上限（G7）: `node scripts/ci/check-size.mjs`。`advisory-db.json` は 2 MB、`dist` 合計は 3 MB（スクリプトの単位は MiB。80% で警告）。
   - §1.2 のチェックリストの例の版や、§1.3 の「320+ tests」は直さなくてよい（テストしない）。
5. **`PRIVACY_POLICY.md`**: 英語と日本語の両方の「Response Headers」の項に、G5 で取得に加える 8 つのヘッダー名（上の A7）を、何のために使うか（セキュリティ診断・キャッシュ診断・技術の推定・WAF の確認画面の検出・レポートの送信先の確認）とあわせて書く。SRI の記述（integrity 属性の有無だけ、値は取得・保持しない）と、Set-Cookie を保持しない記述は残す。`Last updated` の日付は更新してよい（テストしない）。**文面は人が承認する**ので、変更した文面を WORKLOG に書き、完了報告書に載せられるようにする。
6. 完了報告書・check-result.json・総合チェックは、この実装の工程では作らない（§6。スクリプトと報告書の担当が行う）。

テストが前提にしている公開 API（既存）:

- `ALLOWED_RESPONSE_HEADERS: ReadonlySet<string>`（`src/background/service-worker.ts`）
- `readPackageVersion(): string`、`REPO_ROOT: string`（`tests/helpers/release-version.ts`）

## 実装の担当への注意

- **テストに版を書かない規則は src には無い**が、テスト（`tests/`）は変えない。版を上げても既存のテストは package.json から版を取るので、書き換えは要らない（T01）。
- `public/manifest.json` の `permissions`・`host_permissions` は変えない（R04、`tests/service-worker.test.ts` IMPL-08）。版だけを変える。
- `package-lock.json` は自パッケージの `version` 2 か所だけ。`npm install` で作り直さない（依存の記述が変わる）。
- `src/detection/advisory-db.json` の `minExtensionVersion` と、`data/advisories/` は変えない（C13）。
- `report-to` は `SECURITY_HEADER_NAMES` に足すだけ。`HEADER_DEPENDENT_CHECK_PREFIXES` は変えない（新しいチェックではない）。T07 の `SEC-CSPX-REPORT-01` は Reporting-Endpoints だけを見る仕様のまま変えない。
- PRIVACY_POLICY の既存の記述（オンデマンド注入、`chrome.scripting.executeScript`、クエリマスク、Set-Cookie を保持しない、integrity の値を取得しない）は消さない。`tests/service-worker.test.ts` の DOC-08 と、このタスクのテストが見ている。
- README の古い記載の検査（`全125テスト`・`v1.6.0`・`siteChecker/` が無いこと。spec-integrity）に引っかからないようにする。
- 文書・WORKLOG に、作業者のユーザー名・ローカルパス・エージェントの製品名・実サイトのホスト名・作業キットへのリンクを書かない（R03、CI-01 Guard）。
- 予備の文字列の検査は、5 ファイルの `'数字.数字.数字'` の形のリテラルを**すべて**拾う。これらのファイルに版以外の目的で 3 つの数字のリテラルを新しく書かない。
